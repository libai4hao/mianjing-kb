## 一、标签配置表 `label_taxonomy`

迁移 `013_label_taxonomy`（`kb/db.py`）建表：

| 列 | 含义 |
|----|------|
| `level1` | 一级标签（领域，如 Java / 数据库 / AI与大模型） |
| `level2` | 二级标签（知识点，如 JVM / 索引 / RAG） |
| `synonyms` | 别名 JSON 数组（如 `["gc","jvm gc"]`），归一用 |
| `enabled` | 1 启用 / 0 停用（停用后 prompt 与归一都不再出现） |
| `sort` | 排序（一级分组内顺序） |

预设来源与规模：

- `meta/tag_vocab.yaml`：**10 个一级 / 83 个二级**（Java、数据库、缓存与中间件、计算机网络、
  操作系统、前端、AI与大模型、算法与数据结构、项目与行为、工程与质量）；
- `meta/tag_synonyms.yaml`：约 40 条别名 → 二级（如 `jvm gc`→JVM、`hashmap`→集合、`rag`→RAG）；
- seed 只灌空表，`(level1, level2)` 已存在不覆盖——升级不会冲掉人工增删。

### 管理命令

```bash
python -m mianjing_kb.kb.taxonomy --list                       # 按一级分组打印
python -m mianjing_kb.kb.taxonomy --list --json                # 含 groups/aliases/tags/source
python -m mianjing_kb.kb.taxonomy --add "Java/Netty" --synonym netty
python -m mianjing_kb.kb.taxonomy --disable "Java/Netty"       # 或 --disable Netty
python -m mianjing_kb.kb.taxonomy --export meta/tag_vocab.export.yaml
python -m mianjing_kb.kb.taxonomy --seed                       # 从 YAML 补灌缺失项
# 也可走统一入口：kb taxonomy --list
```

### 与打标链路的关系

- `batch_label.build_system_prompt(vocab, tax)`：prompt 的"二级标签"段由配置表的一二级分组渲染，
  不再写死词表；
- `label_one` 用 `taxonomy.load(conn)` 的 `aliases` 做标签归一（`tag_norm_hits` 记录命中数）；
- 表缺失/为空（新库未迁移、测试夹具）自动回退 YAML 快照，工具不因配置缺失崩。

## 二、测试库抽样填充（离线规则）

生产库本轮仍**只读**。测试库路径：

```
D:\my-resource\面经整理ing\21-面经数据库\build\kb_test.sqlite
```

生成方式（可复现，seed=42）：

```bash
python scripts/seed_test_db.py --questions 200
# 200 题 / 41 篇 source_documents；目标已存在时需 --force
```

填充方式（不调 LLM，不花钱）：

```bash
python -m mianjing_kb.batch_label --offline \
  --db "D:\my-resource\面经整理ing\21-面经数据库\build\kb_test.sqlite"
```

实测结果：`todo=200 / labeled=200 / failed=0`；staging 200 行 = `offline` 197 + `manual` 3。
离线规则口径：

- `provider="offline"`、`model="rules-v1"`、`review_state="pending"`——**明确非模型结论**，只用于
  测试库/冷启动预标，不应直接 merge 进正式库；
- qtype：手撕/手写/复杂度→算法，自我介绍/离职→HR，项目/难点→项目，场景/线上→场景，其余八股；
- difficulty：原理/底层/源码→4，区别/是什么→2，其余 3；
- position：前端关键词→前端，Java/MySQL/Redis→后端，算法关键词→算法（≤2）；
- quality：答案 <20 字→残缺，广告词→广告；
- tags：配置表二级标签在题干中命中即取（≤8），无命中回退 `面试题`；
- canonical_q：去题号/项目符号后取题干前 60 字。

## 三、手动打标：模板与回灌

### 1. 生成模板

```bash
python -m mianjing_kb.batch_label --manual-template 20 --db <测试库或生产库>
# 默认输出 <db 同级>/manual_label_template.csv（UTF-8 BOM，Excel 直接打开）
```

模板列（`batch_label.MANUAL_COLUMNS`）：

```
qid,doc_hash,q_text,a_text,topic,qtype,difficulty,position,quality,canonical_q,tags,note
```

- `qid` 必填且必须在 `questions` 存在；`topic/qtype/difficulty` 必填；
- 多值列 `position/quality/tags` 用 `|`（也接受 `;`、`；`）分隔；
- `canonical_q` 留空则回退题干前 60 字；
- 生成时自动跳过乱码/过短/超长题（`textmetrics.garbled_ratio ≥0.01` 或 CJK<0.3 且非 ASCII）。
- 仓库内附示例：`docs/templates/manual_label_template.csv`。

### 2. 回灌

```bash
python -m mianjing_kb.batch_label --manual-import <填好的.csv> --db <同一库> \
  [--manual-dry-run] [--annotator 姓名]
```

- 逐行校验：坏行单独拒绝并报 Excel 行号（第 2 行起），不整批失败；
- 写入 `labels_staging`：`provider="manual"`、`model="human:<annotator>"`；
- 与离线一致走 `labelspec` 校验 + 配置表别名归一（`JVM GC`→`JVM`）；
- 回灌只进 staging，仍需 `--merge`（受 G6/G6b 门禁约束）。

实测：3 行演示数据回灌成功（`imported=3 / rejected=0`），staging 中 `provider=manual` 3 行。

## 四、注意

1. 生产库 `kb.sqlite` 本轮未写；测试库独立文件，可随时 `--force` 重建。
2. 离线/手动行 `review_state=pending`，不能当作"已验收标签"；正式打标仍走 LLM + G6b 金标。
3. `--manual-template` 的 `topic` 预填的是当前库值（通常为空），人工在列上直接改即可。
4. 配置表增删会影响后续打标 prompt 与归一，但**不会**自动重刷历史 staging/历史 questions；
   需要重跑打标或单独回填。
5. T22 仍待做：`position/quality/difficulty` 尚未下沉 `面经库.db`，检索暂无对应过滤。

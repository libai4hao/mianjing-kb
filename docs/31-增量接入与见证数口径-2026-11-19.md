# 增量接入与见证数口径（Q-2 / Q-3）

> 状态：现行 · 最后更新：2026-11-19 · 适用版本：v2-R3

本篇记录两项已拍板口径的落地：**Q-2 见证数改用 `distinct collection`**、**Q-3 实现
`processing/processed` + `document_products` 并支持增量抽取**；文末是代码↔文档一致性核查结果。

## 1. Q-2：见证数 = distinct collection

**口径**：同一 `collection` 下的多篇文档只算 1 个来源；`collection` 为空时回退到自身
`doc_hash`（不能把未知来源全并成 1 个，也不能按文档数虚高）。

落地：

| 位置 | 变化 |
|---|---|
| `meta/schema` → `kb/db.py` 014 | 重建 `question_freq` 视图：新增 `n_distinct_collections`，`HAVING` 改按来源集；保留 `n_distinct_docs` 兼容旧报表 |
| `canonical.build_rows` | `canonical_questions.witness` 不再取簇内文档数，改取 distinct collection |
| `report.build_clusters` / 报告 / CSV | 新增 `witness`、`n_collections`；排序改为"来源集优先、文档数次之"；"多来源簇"按 `witness>=2` |
| `extract --stats` | 仍输出 `n_distinct_docs`，视图里同时可取 `n_distinct_collections` |

**影响（产库只读实测，未重跑）**：`questions` 涉及 2,143 个 doc_hash，但只对应 **152 个
collection**；`source_documents` 里 1,515 行有 153 个非空 collection、63 行 collection 为空。
即同一道题的"见证数"在重算后整体会显著下降（量级约十几倍），Top 榜不能与旧榜混用
（旧口径见 `docs/29` §4）。

## 2. Q-3：状态真写 + 产物台账 + 增量

### 2.1 状态机

| 状态 | 谁写 | 含义 |
|---|---|---|
| `classified` | `classify` | 内容池入口（待处理） |
| `processing` | `extract` 开始 | 处理中；崩溃后由此续跑；**失败也留在此态** |
| `processed` | `extract` 成功落题后 | 已抽题（含 0 题的件）；增量默认跳过 |

- `status.INGESTED = (classified, processing, processed)` 成为题池/建库/G1/G5 的统一口径；
  `mdmap`、`build_db`、`verify_ledger.g1/g5` 均已改用它，避免"变成 processed 就被踢出题池"。
- `failed` 仍没有写入方：失败保留 `processing`，下次增量会重试；这是"断点"而不是"终态"。
- `ingest_queue` 视图仍只收 `classified`（它是"待处理队列"，不是内容池）。

### 2.2 `document_products`（015 迁移）

一行 = 一个输入身份的处理结果：`md_rel / md_hash / text_source(md|source|orphan) /
gate_verdict / questions_n / input_size / input_mtime / extracted_at / indexed_at`。

- `extract` 开始前先把 mdmap 的映射同步成产物行（`extracted_at` 留空）；
- 每篇抽完写 `questions_n` 与 `extracted_at`，并置 `processed`；
- `indexed_at` 预留给 `refresh`（当前 NULL）。

### 2.3 增量判据与安全边界

```powershell
python -m mianjing_kb.extract --incremental
```

- 需要处理：没有产物行 / 没抽过（`extracted_at` 为空）/ 输入文件 `size` 或 `mtime` 变了；
- 没变的件跳过，输出 `skipped_unchanged`；
- **只有全量跑才 `purge_orphans`**：增量只处理子集，purge 会误删未在本次池里的题；
- 每 50 篇提交一次，崩溃只回退当前块；
- 文件内容变了才会重抽（size/mtime 判据），同名但内容不变的文件不会反复处理。

## 3. 代码与文档一致性核查

新增 `mianjing_kb.doc_audit`（`python -m mianjing_kb.doc_audit`，`--json` 可机读），只查
机器可判定的漂移：

1. `kb/status.py` 的 `ALL` vs `001_init.sql` 的 CHECK 枚举；
2. `docs/19` 的状态机清单 vs `status.ALL`；
3. `docs/03` §10.4 状态表是否只使用已登记状态；
4. `docs/15` 门禁表 vs `verify_ledger` 实际 `_gate(...)`，且 `refresh.REQUIRED_GATES` 全部在文档表；
5. `docs/README.md` 是否收录每一份 `docs/*.md`、引用文件是否存在；
6. 每份现行 docs 是否带状态头。

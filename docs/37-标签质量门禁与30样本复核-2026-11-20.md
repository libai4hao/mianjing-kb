# 37-标签质量门禁与 30 条样本复核（2026-11-20）

## 1. 结论

人工复核 30 条试跑样本（10 其他 + 10 代码碎片 + 10 随机正常）后，问题不是“标签分布不均”，
而是**切题把非题内容送进了打标**：

- 30 条中只有 **17 条是明确面试题**，1 条部分成立，**12 条不是题**（10 条代码行 + 2 条章节/多题粘连）。
- 题干完整仅 13 条，15 条被硬切/拼接，2 条部分完整。
- 答案匹配仅 4 条；18 条无答案，5 条答非所问，3 条部分匹配。
- 模型给出的 30 条 `issues` **全部为空**——`validate_label` 只校验枚举/范围，识别不了
  “代码行被当题”“题干被截断”“topic 语义错”。
- 按人工建议标签，**14/30 的 topic/qtype/difficulty 需要改**；其中 10 条碎片应直接 reject。

因此门禁必须卡在**切题产物进入打标之前**，而不是等模型打完再调分布。

## 4. 根因定位

| 根因 | 代码位置 | 说明 |
|---|---|---|
| 代码行成题 | `mianjing_kb/chunker.py::chunk_v2` + `extract.py::_rows_from_text` | docx 无 Markdown 代码围栏，代码行被当问句/标题；`_rows_from_text` 无 `is_code_fragment` 出口 |
| PDF 题干硬切 | `chunker.py::chunk_v2` 的行级切分 + `extract.py::_rows_from_text:249` | `q_text=it["q"][:2000]` 原样落库，没有把下一行续回题干 |
| 章节说明/多题粘连 | `chunker.py` 标题识别 + `_split_answers` | “大题(五道选两道…)”被当题干，答案区把多道题拼在一起 |
| 碎片仍送模型 | `batch_label.py::pick_targets` | 旧实现不跳过 `is_code_fragment`，碎片消耗 LLM 并产出幻觉标签 |
| 语义错标无法发现 | `labelspec.py::validate_label` | 只校验枚举/范围；`issues` 为空不代表标签正确 |
| pending 绕过复核 | `batch_label.py::merge` | 旧实现只排除 `disagree`，`pending` 会被静默 merge |
| 上下文丢失 | `batch_label.py::label_one` | prompt 只取题干/答案各 300 字，缺 `file_name/source_topic/前后文`，产品题更易归“其他” |
| 技术上下文被删 | `llm_client.py::redact` | 旧实现把 URL 也替换成 `[联系方式]`，技术文档链接被误删 |

## 5. 质量门禁设计

1. **抽取层（不直接删题）**：`is_code_fragment` 只做标记/拦截打标，不直接删除生产题，
   避免误杀“假设已有函数 `int recv(char*, int);`”这类正常题干；命中进入 `reject/fragment` 审核队列。
2. **打标层**：`pick_targets(skip_code=True)` 默认跳过碎片；`label_one` 写
   `label_trace.jsonl` sidecar，保留 `raw_response/issues`；prompt 增加文件/来源上下文。
3. **复核层**：`pending` 一律不得 merge；`--review-resolve` 是唯一出口。
4. **Merge 层**：`label_quality.assess` 硬拦
   - `code_fragment > 0`
   - `pending > 0`
   - 批次 ≥20 且 `其他` 主题率 >25%；15%–25% 记 WARN。
5. **回归层**：样本集冻结 qid，重跑同一批；每轮记录 `other_rate/fragment_rate/pending_rate/
   label_changed`，防止“分布变好看但依据变差”。

## 4. R2 判断的复核结果（哪些变了、哪些没变）

**没变（R2 原文继续有效）**：解析主路 pymupdf4llm、质量门禁替代文本层判断、本地 OCR 零预算、
合并版源标记选 a（抽取层读书签，未重转）、见证数题级口径、8 GB 显存降档、C 盘不放任何东西。

**变了**：
1. **判重处置矩阵里 D2/D3 仍以人工+留痕为主**：像素指纹 `fingerprint.py` 未建，D3 跨格式由合并轮人工完成 2 对 +
   cluster 结果佐证；机器化降级为 P2 可选项（当前增量导入主要靠 D1 hash + D4 题级，够用）。
2. **拆题口径从"题号唯一"改为"四类信号"**：R2 §5.3 的"按书签段+######小标题"是合并版专用路径；
   chunker v2 把问句/标题+讲解/考点+答案也纳入，且答案内编号列表不判新题（R2）、问词行中误命中限行首 8 字（R3 新坑）。
3. **`ingest_queue` 视图口径**：`dir_path NOT LIKE '99-重复文件待删%'` 过滤固化（D-20 的路径统一使然）。

## 6. 风险表（R3 增量 3 条）

| 风险 | 征兆 | 预案 |
|---|---|---|
| **LSH 近重复漏召** | hamming 很小但四条 16bit 带都不撞（实测 ham7/jac0.93 未合并） | 频次报告按"候选+双重确认"口径理解；精确同文组永远全量 |
| **同名输出覆盖** | 不同源同 stem 转到同一 `20-题库MD` 路径，后转覆盖先转（已发生 26 条） | 重转时输出名带 doc_hash 后缀；`reconcile.py` 可重跑对账 |
| **kb 双实例** | `kb` 与 `tools.kb` 是两个模块对象，配置注入测试静默失效 | `kb/__init__.py` setdefault 别名 + conftest 预导入（已修，63 tests） |
| （沿用 R2）删 99 区过早 / 合并版伪单源 / 派生树回流 / 散副本夺主 / 跨格式漏判 / C 盘告急 | — | gate 已走通一轮，规则均固化有用例 |

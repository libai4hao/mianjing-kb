# 聚类评测与质量指标（P1）

> 状态：现行 · 最后更新：2026-11-19 · 适用版本：v2-R3

本篇只回答一个问题：**题级去重/聚类的质量，现在能不能用数字证明？**
答案是"部分能"：格式级近重复已可量化，真改写（paraphrase）当前几乎全漏。
基线数字是**未重跑 P0-1 的产库口径**（`kb.sqlite` 32,087 行），重跑后需整体重算（见 `29` §4）。

## 1. 落地内容

| 文件 | 作用 |
|---|---|
| `eval/cluster_pairs.yaml` | 60 对固定评测集：30 同题 / 30 不同题，分 `normalize / paraphrase / hard_neg / long_noise` 四类；`review_state: draft` |
| `mianjing_kb/eval_cluster.py` | 逐对判定（与 `question_freq.cluster` 同判据）+ P/R/F1 + 分组指标 + 阈值扫描；另出语料指标（题长分布、答案覆盖、coverage、leftovers） |
| `tests/test_eval_cluster.py` | 11 例：加载校验、判据、混淆矩阵、分组、扫描、DB/MD 指标、CLI 退出码 |
| `build/cluster_eval_report.md` | 每次运行的报告（不入库，产物） |

运行：

```powershell
python -m mianjing_kb.eval_cluster --sweep                       # 全量：成对 + 扫描 + 产库/语料指标
python -m mianjing_kb.eval_cluster --skip-corpus --min-f1 0.4    # 只跑成对，可挂 CI 冒烟
```

判据与生产一致：先做 `normalize`（去标点/空白/大小写），再用 SimHash 汉明距离 ≤ `dist`（默认 24）**且**字 2-gram Jaccard ≥ `jac`（默认 0.7）。

## 2. 基线结果（2026-11-19，评测集 draft）

| 指标 | 值 | 判读 |
|---|---|---|
| Precision | **0.9091**（TP 10 / FP 1） | 合并很保守，几乎不误合并 |
| Recall | **0.3333**（TP 10 / FN 20） | 大量真改写被判成不同题 |
| F1 | **0.4878** | — |

分组（同一阈值 24 / 0.7）：

| kind | n | P | R | 说明 |
|---|---|---|---|---|
| normalize | 10 | 1.0000 | 1.0000 | 空格/标点/题号差异全部抓住 |
| paraphrase | 20 | — | **0.0000** | 20 对真改写**全部漏合并** |
| hard_neg | 28 | — | — | 仅 1 个误合并：`进程和线程的区别` vs `协程和线程的区别`（hamming 6 / jac 0.75） |
| long_noise | 2 | — | — | 未误合并（长文把 Jaccard 拉低，天然被挡） |

结论：**现在的"同题聚类"实际只等于"格式归一化"**。`canonical` 的 13,716 个簇里，
真正同义改写的题基本各自成簇；P1-4 频次榜的"见证数"仍是保守下界。

阈值扫描（60 对，节选）：

| dist | jac | P | R | F1 | FP |
|---|---|---|---|---|---|
| 24 | 0.4 | 0.6818 | 0.5000 | 0.5769 | 7 |
| 24 | 0.5 | 0.6875 | 0.3667 | 0.4783 | 5 |
| 24 | 0.6 | 0.9091 | 0.3333 | 0.4878 | 1 |
| **24** | **0.7** | **0.9091** | **0.3333** | **0.4878** | **1** |
| 24 | 0.8 | 1.0000 | 0.2667 | 0.4211 | 0 |

F1 最高的点（`jac=0.4`）靠 7 个误合并换来 +17 个召回，精度掉到 0.68；
**不建议把默认阈值改成 0.4**：编目场景里误合并会把两道不同的题永久并成一簇，代价高于漏合并。

## 3. 语料侧指标（同次运行）

题长与答案（`kb.sqlite`，32,087 行）：

| 指标 | 值 |
|---|---|
| 题干字符 p50 / p90 / p99 / max | 23 / 50 / 196 / 2000 |
| 题干 >120 token | 331（1.03%） |
| 答案覆盖率（`a_text` ≥20 字） | **0.7548** |
| 空答案 | 6,752（**21.04%**） |

切题（`20-题库MD` 1,434 篇，`chunk_v2` 重算）：

| 指标 | 值 |
|---|---|
| coverage（micro / p10 / p50 / p90） | **0.9638** / 0.0 / 0.9805 / 1.0 |
| 未识别正文占比 | **0.0343**（1,398,605 字符） |
| 0 题文档 | **180 篇（12.6%）** |

`coverage p10 = 0` 与 180 篇 0 题文档是同一件事：这批文档切题器完全没认出题目，
`coverage` 再高也不代表"抽到了东西"。这比聚类阈值更值得先修。

## 4. 口径与限制（引用数字前必读）

1. **这是成对（pair-level）指标，不是簇级 P/R**。传递闭包会把 A-B、B-C 并成 A-B-C，
   成对 FP=1 也可能在簇级放大。要严格簇级指标，需要对整簇标注，不在本轮范围。
2. `review_state: draft`：60 对由代码作者起草，**未逐条人工复核**。在改成 `reviewed` 前，
   这些数字只能作趋势与回归对比，**不得当验收阈值**，更不得据此调生产默认参数。
3. 答案覆盖率的定义是"`a_text` 非空且 ≥20 字"，不等于"答案正确/完整"；
   同题异答是否被覆盖，要靠 `question_variants.answering_text` 的簇内比对，尚未评测。
4. 产库仍是 P0-1 修正前的口径（含 20,570 行镜像身份题）；重跑 `extract` → `refresh` 后，
   本页 §2/§3 必须整体重算，不能沿用。
5. 文档级近重复（重新导出/格式转换/OCR 后 SHA256 变化）**本次未接入**：
   `intake` 仍只认字节 hash。原 T7 观察项 `char_fingerprint` / `pixel_fingerprint`
   已于 2026-11-21 删除（无生产调用、观察期届满）；跨长度包含度判定保留 `threshold_fingerprint`
   / `threshold_containment`。若将来要接文档级近重复需重新设计，不能靠题级聚类兜底，也不能复用已删的像素/字符指纹。

## 5. 建议的下一步（按收益排序）

1. **先修 180 篇 0 题文档**：按 `leftovers.why=未识别正文` 抽样，补切题信号（表格题、无问号祈使句、
   代码题）；这批是纯漏抽，不涉及聚类判据。
2. **把评测集复核到 `reviewed`**：至少两人独立标一遍，争议条目删除；再决定是否把 `--min-f1` 挂 CI。
3. **真改写不要压 Jaccard 阈值**：在 S4 增加"语义候选召回"（embedding 近邻只做候选，
   仍由规则/人工复核决定是否同簇），保持当前高精度默认不变。
4. **补簇级评测**：抽 30 个多文档簇人工判"是否同一题"，直接测簇级 P/R，替代成对代理。
5. **再接文档级指纹**：原 T7 观察项（`char_fingerprint` / `pixel_fingerprint`）已于 2026-11-21 删除；
   如仍要做需重新设计"hash 不同但文件名/大小接近"的二次判定（生产判重走 sha256/doc_hash，
   跨长度包含度用 `threshold_containment`），先只报警不自动合并。

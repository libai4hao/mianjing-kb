## 4. 已知失真（必须先说明，再引用）

**P0-1 双身份**（`docs/27`）：题池同时收"源文件（内容 hash）"和"`20-题库MD` 镜像（`md-mirror:` 路径 hash）"，
同一原文被抽两遍 → 题数、见证数、簇数、频次榜全部偏大。

因此下列结论在使用本表时必须附带说明：

- **32,087 不是"32,087 道不同的题"**；题干层面只有 14,446 个不同 `q_norm_hash`。
- **`Top 题 24/32 文档`** 这类排名不可用于"热度/重要性"判断，先按 P0-1 修正再重算。
- `docs/07-题目频次报告`、`docs/06-R3` §2.2 的覆盖率（73.8%）与 Top 榜**均属旧口径**。
- 修正后的预期量级：题行约 **2 万**（约 11,500 源侧 + 991 仅有 md 的件），需重跑 `extract` → `refresh` 后以新表为准。
- **修复代码已落地（2026-11-19）**：`kb/mdmap.py` 单身份映射 + 门禁 `G8`（`verify_ledger.g8_single_identity`，已进 `refresh.REQUIRED_GATES`）。
  但生产 `extract` 尚未重跑，本文件 §2/§3 数字仍是旧口径；重跑后需整体重写本文件。
- **见证口径已改（Q-2，2026-11-19）**：`canonical_questions.witness` 与 `question_freq.n_distinct_collections`
  改按 distinct `collection` 计数（014 迁移），collection 为空的件回退自身 `doc_hash`。
  因此旧"文档数=见证数"的榜（`docs/07`、`docs/21`、`06-R3` §2.2）不能与重算后的数字混用。

## 5. 统计 SQL（可直接跑，只读）

```sql
-- 0) 一律只读打开
-- sqlite3.connect("file:<path>?mode=ro", uri=True)

-- 1) 台账分布（kb.sqlite）
SELECT status, COUNT(*) FROM source_documents GROUP BY 1 ORDER BY 2 DESC;

-- 2) 题/簇（kb.sqlite）
SELECT COUNT(*) FROM questions;                        -- 32,087
SELECT COUNT(DISTINCT q_norm_hash) FROM questions;     -- 14,446
SELECT COUNT(DISTINCT doc_hash) FROM questions;         -- 2,143
SELECT COUNT(*) FROM canonical_questions;               -- 13,716
SELECT COUNT(*) FROM questions WHERE COALESCE(a_text,'')='';        -- 6,175
SELECT COUNT(*) FROM questions WHERE LENGTH(COALESCE(a_text,''))<20; -- 7,808
SELECT COUNT(*) FROM (SELECT doc_hash,q_norm_hash,COUNT(*) c
  FROM questions GROUP BY 1,2 HAVING c>1);               -- 1,209

-- 2b) 见证口径（Q-2，2026-11-19）：distinct collection，空 collection 回退 doc_hash
SELECT COUNT(DISTINCT COALESCE(NULLIF(TRIM(sd.collection), ''), 'doc:' || q.doc_hash))
  FROM questions q LEFT JOIN source_documents sd ON sd.doc_hash = q.doc_hash;  -- 当前 152
SELECT COUNT(DISTINCT sd.collection) FROM source_documents
  WHERE collection IS NOT NULL AND collection <> '';                            -- 153
SELECT COUNT(*) FROM source_documents WHERE collection IS NULL OR collection=''; -- 63
-- 题级见证示例：同一 q_norm_hash 的来源集数（视图 question_freq.n_distinct_collections）

-- 3) 双身份（面经库.db）
SELECT COUNT(*) FROM questions WHERE doc_hash NOT IN (SELECT doc_hash FROM documents); -- 20,570
SELECT COUNT(*) FROM doc_contents WHERE doc_hash IS NOT NULL;      -- 1,364
-- 同一原文两边都出题：按 doc_contents 逐条比 questions(doc_hash) 与 questions(mirror_hash) 均 >0

-- 4) 索引一致性（门禁 G4 口径，仅比数量/集合，不含同源校验）
SELECT (SELECT COUNT(*) FROM questions) AS q,
       (SELECT COUNT(*) FROM vec_questions) AS vec,
       (SELECT COUNT(*) FROM questions_fts) AS fts;
```

注意：G4 的 SQL **不能**证明"向量与题目同源"（`docs/27` P0-2），需要内容抽样才有意义。

## 6. 引用规矩

1. 引用数字必须写成「**数字 + 时点 + 口径**」，例如"2026-11-19 快照，`questions` 行 32,087（含镜像身份）"。
2. 历史文档（`docs/21`、`07`、`06-R3` §2 等）里的数字**只能作为历史引用**，不得在 README、汇报、对外材料里当现状。
3. 快照更新流程：跑 §5 SQL → 改本文件「快照时间」与各表 → 同时回填 `docs/19` 若涉及流程变化 → 在 `待办清单` 记一条。
4. 若 `27` P0-1 修复完成，本文件 §3/§4 必须整体重写（不是打补丁），并在 `docs/README.md` 记录版本。

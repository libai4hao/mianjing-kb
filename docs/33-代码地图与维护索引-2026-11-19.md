## 8. 审查重点与已知边界

- `qid` 只是行号，跨库/跨批次定位用 `q_key = doc_hash:q_norm_hash`；不要把 `qid` 写进外部契约。
- `label_facts` 按 `q_norm_hash` 共享语义标签，不是按 `q_key`；`normalizer_version`/`q_norm_sample` 用于归一规则升级时重算/迁移，不要整表删。变体/依赖链用 `q_key`，两者独立。
- `question_tags` / `difficulty` / `tags_json` 在检索库的值为空，是因为生产尚未全量打标，不是 `build_db` 没代码；过滤功能要等打标后验证。
- `gate_results` 以 `md_path` 为主键，`--md-dir` 行 `doc_hash=NULL`；只有 `--audit` 行能参与 `extract` 的 `doc_hash` 前置过滤。同路径多源覆盖会让 `gate_results` 行数少于产物数（生产 399 产物 → 385 行），完整结论以 `source_documents.gate_result` 为准。删除/移动 md 后的旧 `--md-dir` 行按目录前缀清理，跨目录残留需人工核对。
- `extract` 默认只跳过已有 review/fail 结论的文档，无台账仍抽；全量启用 `--require-gate` 前要先跑 `gate --audit`，否则新克隆会一篇都抽不出来。生产 `gate --audit` 只覆盖 `convert_log` 的 423 件，`pool` 1,466 篇里仍有 1,058 篇 `ungated`；`--require-gate` 只适合“先门禁后抽题”的新批次，不适合对现存全量重抽。
- `pass` 只代表“没有可识别的非中文垃圾字符 + 长度/CJK 达标”，不等于可读；ToUnicode 错映射成正常汉字的 mojibake 不在字符白名单能力内。
- `refresh` 持有 kb 写锁贯穿 reembed，长任务期间 `intake` 会拿不到锁；这是已记录的取舍，不是缺陷。
- 新克隆没有 `meta/skip_log.json` 时 G1 会 FAIL；该文件是个人数据，必须在目标机重新生成或本地保留。
- Windows Word COM 单点；拿不到 WINWORD PID 时可能残留空实例，T16 已定为已知边界。
- `kb/hashing.py` 的 `char_fingerprint` / `similarity` / `pixel_fingerprint` 已于 2026-11-21 删除（T7 观察期届满、无生产调用）；
  现保留 `threshold_fingerprint` / `threshold_containment` 做跨长度包含度判定，生产判重走 sha256/doc_hash。
  注意 `canonical.py:272` 的 `similarity(a: str, b: str)` 是同名不同签名的独立函数，勿混淆。

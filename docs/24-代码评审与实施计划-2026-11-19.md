## 一、结论

1. 七项改造（T11 分块提交、T12 事件表、T13 状态常量、T14 迁移事务化、T15 写锁、T17 convert_one 入仓、
   T19 裸 converted_to 校验）的主路径是对的，生产库实测 G5 PASS、`legacy_converted_checked=47`。
2. 本轮修掉 8 个真问题，其中 3 个属"可能静默出错"级别：写锁误删他人锁、G5 裸目标多候选取第一条假 PASS、
   doc_convert 末尾一次性提交导致崩溃丢账。其余是提示过期、语义读反、测试导入顺序依赖。
3. 剩余问题都不阻塞当前使用，按批次排进计划（见第四节），不在评审里顺手扩改结构。

## 四、后续实施计划

### 4.1 顺序与依赖

先定标签 schema，再批量 prompt，再金标评测，最后标签进检索——顺序反了会返工：
schema 变一次，prompt、金标、G6、检索字段全要重跑。

```
T21 标签体系/schema ──► T23 批量 prompt ──► T20 金标 500→1000 ──► 全量打标 ──► T22 标签进检索
                                                        │
                                                        └─► G6b 转为真实硬门（此后 --merge 受准确率约束）
```

### 4.2 各条拆解

**T21 标签体系补全（已完成 2026-11-19，落地记录见 `docs/25`）**

- 产物：`meta/label_schema.yaml`（每维：枚举/范围/单多选/上限/是否必填）；迁移 `012_label_columns`
  给 `questions` 加 `position TEXT`（JSON 数组）、`quality TEXT`（JSON 数组）、`canonical_q TEXT`；
  `batch_label` prompt 由 schema 渲染，不再手写枚举；`tags` 走"开放提取 → 同义词表归一 → 高频沉淀二级词表"。
- 词表起点：一级 10~20（沿用 topic 并集裁剪）、二级 50~150（从现有 32k 题高频 tag 提取）；
  每题上限 8 个标签（topic/qtype/difficulty 之外）。
- 验收：G6 覆盖新维度枚举；同义标签合并率可量化（抽样 200 题人工核对）；
  `canonical_q ≤60 字`、`position ∈ {后端,前端,算法,测试,客户端,数据,其他}`。

**T23 单题单调用 → 批量 prompt（1.5 天，依赖 T21）**

- 每批 8~16 题，输出 JSON 数组、显式 `qid` 对齐（顺序不作匹配依据），单批 token ≤ 上下文 50%~70%；
  失败批按 qid 拆小重试，仍失败落 `label_failed.jsonl`。
- 成本：32,087 题从 32k 次调用降到约 2.7k 次（12 题/批）；先拿 500 题对比"批量 vs 单题"的 G6 合格率。
- 验收：调用次数降一个数量级；同集 label 结果与单题版差异有记录（topic 一致率 ≥0.95 才推全量）。

**T20 打标质量评估（2 天代码 + 1~2 天人工，依赖 T21/T23）**

- `--golden-export 500` 分层抽样（topic × qtype × 来源目录），人工填 `topic_gold`（必填）、
  `qtype_gold/difficulty_gold`（可空）→ `--golden-load` 回灌；`--eval` 出混淆矩阵与弱主题；
  按错误分布改词表/prompt，同集重跑对比，再扩到 1,000 固定为回归基线。
- 门槛：topic 准确率 ≥0.8 才允许 `--merge`（G6b 已是硬门，`golden_labels` 有数据后从 SKIP 转真判）。
- 验收：`golden_labels ≥500`；两次评测 weak_topics 有前后对比；G6b 出现真实 PASS/FAIL。

**全量打标（0.5 天机器时间 + 抽检）**

- 先跑 3,000 题看 G6 合格率与失败分布，再全量；失败题进 `label_failed.jsonl`，不阻塞主流程。
- 预算按 T23 后 ~2.7k 次调用估，注意 provider 限流（并发沿用现有线程池，失败退避）。

**T22 标签进检索（2 天，依赖全量打标）**

- `面经库.db.questions` 增 `difficulty / tags_json / position / quality`；`docs_fts` 之外建 `tags_norm` 索引；
  `search` 增 `--difficulty / --position / --quality`；标签只做过滤与重排特征，不替代 kw+vec 两路召回。
- 验收：`--difficulty 4 --position 后端` 在 k=10 下不空；`eval_retrieval` hit@k 不回退（基线先存档）。

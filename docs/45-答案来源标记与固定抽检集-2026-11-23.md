## 1 答案来源标记（`questions.answer_state`，迁移 018）

问题：`docs/43` 把"答案为空"一律算进缺陷率，其中大半是源文档本身只列问题（面经回忆、题库清单、
PDF 目录被当正文），拿它扣切块质量会误判，也说不清到底是抽取坏了还是素材就那样。

新增列 `answer_state`（迁移 `018_answer_state`，`python -m mianjing_kb.answer_state --apply` 回填）：

| 值 | 含义 | 抽检口径 |
|---|---|---|
| `ok` | 原文有答案 | 主分母 |
| `no_answer_source` | 该文档过半题都没答案——来源只列问题，不是切块 bug | **口径外**，不扣准确率 |
| `boundary_gap` | 同文档多数题有答案、这条却空——疑似切块错位/答案被邻题吃掉 | 计入分母，重点修 |
| `toc_noise` | 连续 ≥8 块空答案且标题式 ≥80% 的目录区伪题 | 计入分母，候选退役 |

判定只看结构：文档级答案覆盖率 ≤ 0.5 记 `no_answer_source`，否则记 `boundary_gap`；目录区用
`qsalvage.toc_runs()` 覆盖。当前分布（19,913 题）：

```
ok 14,645（73.5%）  no_answer_source 2,654  boundary_gap 2,526  toc_noise 88
```

`python -m mianjing_kb.status` 已增加「答案来源」一行，日常就能看到；老库没跑 018 时该行自动省略
（`status._column_exists` 做了兼容）。

## 2 固定抽检集（`eval/qcheck/set-20261123.json` + `mianjing_kb.qcheck`）

`docs/43` 的 55 题是一次性样本，改完没法对比。现在固定一批题，改前改后都看同一批：

```
python -m mianjing_kb.qcheck make   --db <kb.sqlite> --n 200 --seed 20261123 \
        --carry <旧 result.json> --out eval/qcheck/set-20261123.json
python -m mianjing_kb.qcheck render --db <kb.sqlite> --set <set.json> --out <dir>
python -m mianjing_kb.qcheck stats  --set <set.json> --labels <labels.json>
```

- 分层：`ok` 120 / `boundary_gap` 40 / `no_answer_source` 30 / `toc_noise` 10（按 `--n` 等比缩放）。
- `--carry` 把旧抽检里已判定过的 qid + 标签带进来，保证连续性：本次 **253 题（200 新 + 53 沿用）**。
- 统计同时给两个口径：全样本严格准确率，和「有答案口径」（排除 `no_answer_source`）。

当前样本的已有标签（53 条，来自 `docs/43` 那轮）：

| 口径 | 判定 | 严格准确率 | 可用率 |
|---|---|---|---|
| 全样本 | pass 14 / partial 10 / fail 29 | 26.4% | 45.3% |
| 有答案口径（ok+gap+toc） | pass 14 / partial 10 / fail 15 | **35.9%** | **61.5%** |

差出来的 14 条 fail 全在 `no_answer_source` 桶——这就是"标记"的价值：切块质量其实是 35.9%，
26% 那个数字被素材缺答案拖下去的。200 条新样本待标，标完即成为下一次改动的对照基线。

# 5,000 题小排量预生产测试方案（2026-11-19）

> 状态：现行 · 最后更新：2026-11-19 · 适用版本：v2-R3
> 结论：**可以做隔离的影子试跑，不能直接对生产库做写入测试。**
> 本方案只写“怎么试、怎么验、何时停”，不替代 D-27 的生产迁移审批。

## 1. 结论与边界

### 1.1 当前能不能做

| 口径 | 结论 | 原因 |
|---|---|---|
| 直接在生产 `kb.sqlite` 上抽 5,000 题 | **不可以** | 生产已完成 D-27 的 016/017/qnorm 迁移，但预生产试跑仍必须隔离，避免写入与发布互扰 |
| 在生产库副本 + 独立 build 目录上跑 5,000 题 | **可以，已提供一键准备** | 不触碰生产库和线上 `面经库.db`，可完整验证 S4–S6 链路 |
| 用新标签体系跑 5,000 题打标 | **暂不可以（100 题冒烟可以）** | 标签 v2 的稳定 ID、题型/难度/质量字段尚未落库；配好 key 后只跑 `--limit 100` 冒烟，见 5.6 与 `docs/36` |
| 用 Golden Query 做检索质量验收 | **可以，作为候选基线** | D-34 已建立 50 条候选与 Recall@5/MRR@10/nDCG@10；首版仍 `reviewed: false`，只能作为试跑报告，不冒充发布硬门禁 |

### 1.2 “小排量生产测试”的准确定义

本轮建议定义为：

- **真实语料**：从生产库的 20,010 题中抽取约 5,000 题对应的文档；
- **真实链路**：extract → canonical → build_db / embed → refresh gates → search；
- **影子写入**：所有写入只落在 `pilot/5000/build` 和 `pilot/5000/corpus`；
- **生产只读**：生产 `kb.sqlite`、`面经库.db` 只读打开，不执行任何迁移、不写任何行、不替换任何文件；
- **可丢弃**：测试结束整目录删除即可，不需要“回滚生产”。

不满足以上任一条，就不叫小排量预生产测试，而是生产变更。

## 2. 前置检查（任何写操作之前）

### 2.1 生产库只读核对

必须用 `mode=ro` 打开生产库，禁止 `db.connect(create=True)`：

```powershell
$prodDb = '<PROD_DB>'
kb preflight --db $prodDb --json
```

`preflight` 只读打开，输出 `schema_version`、`applied_versions`、`pending_migrations`、`integrity_check`、`quick_check` 和关键计数；不要用 `docs/29`/`docs/32` 的快照数字代替它。

手工兜底命令：

```powershell
$prodDb = '<REPO_ROOT>\build\kb.sqlite'
& '<PYTHON>' -c @"
import sqlite3, json
from pathlib import Path
p = Path(r'$prodDb').as_posix()
con = sqlite3.connect(f'file:{p}?mode=ro', uri=True)
print(json.dumps({
  'schema_version': con.execute('SELECT MAX(version) FROM schema_version').fetchone()[0],
  'integrity': con.execute('PRAGMA integrity_check').fetchone()[0],
  'questions': con.execute('SELECT COUNT(*) FROM questions').fetchone()[0],
  'docs': con.execute('SELECT COUNT(DISTINCT doc_hash) FROM questions').fetchone()[0],
  'products': con.execute('SELECT COUNT(*) FROM document_products').fetchone()[0],
}, ensure_ascii=False, indent=1))
"@
```

判定：

- `integrity_check` 必须是 `ok`；
- `schema_version` 必须记录到测试报告，不能凭 `docs/29`/`docs/32` 推断；
- 生产已于 2026-11-19 完成 016/017/qnorm（见 `docs/34` D-27 实施记录），但试跑仍只允许对副本执行 `kb refresh`。

### 2.2 备份与副本

用 SQLite Backup API，不要 `Copy-Item` 主文件（会漏 WAL）：

```powershell
$pilot = 'D:\pilot\5000'
New-Item -ItemType Directory -Force -Path "$pilot\build", "$pilot\corpus\20-题库MD" | Out-Null
& '<PYTHON>' -c @"
import sqlite3
from pathlib import Path
src_path = Path(r'$prodDb').as_posix()
src = sqlite3.connect(f'file:{src_path}?mode=ro', uri=True)
dst = sqlite3.connect(r'$pilot\build\kb.sqlite')
src.backup(dst)
dst.commit(); dst.close(); src.close()
"@
```

备份后立即对副本做 `PRAGMA quick_check`，失败则停止。

### 2.3 磁盘与锁

- 预留至少“生产库大小 × 2 + 1 GB”；
- 确认 `build/locks` 下没有活跃 `kb.lock`/`online.lock`；
- 测试期间不运行会写生产库的 intake/extract/refresh/label/embed/purge。

## 3. 5,000 题切片

### 3.1 当前工具的限制

`extract --limit N` 限制的是**文档数**，不是题数；一键入口用“目标题数”反推文档数：

- 生产基线约 20,010 题 / 1,212 个有题文档 ≈ 16.5 题/文档，但同一 MD 被多个身份共享，按生产 `questions_n` 直接抽会重复计入；
- `prepare` 对候选文档做一次无写入抽取估算（同一物理文件只选一次，跳过 `non_content`），按 `target_min=4500`、`target_max=5500` 累计截断；
- 本次 `seed=7` 实际选出 **121 个文档 / 估算 4,544 题**，在区间内；`run` 后以实际题为最终口径。

如果要按主题比例抽样，需要等标签 v2 回填 `questions.topic`；当前只做整体随机抽样。

**当前已提供一键准备**：

```powershell
python -m mianjing_kb.pilot5000 prepare --config D:\pilot\5000\config.json
```

`prepare` 会写 `pilot_docs.csv`、`pilot_plan.json` 并复制 MD 产物；生产库只读，副本写入 `<pilot_root>/build`。`pilot_plan.json` 的 `docs`、`target_questions` 是选样结果，`run` 后实际题数落在 4,500–5,500 即视为达标。

### 3.2 手工复算 SQL（历史参考，topic 为空时不可用）

生产 `questions.topic` 目前全为 NULL，按 topic 分层会把所有文档归入“未分类”；下面 SQL 仅作为标签 v2 回填后的复算模板，不是一键入口的执行路径。

```sql
WITH doc_stats AS (
  SELECT q.doc_hash,
         COALESCE(NULLIF(q.topic, ''), '未分类') AS topic,
         COUNT(*) AS n
  FROM questions q
  GROUP BY q.doc_hash, 2
), ranked AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY topic ORDER BY n DESC, doc_hash) AS rn
  FROM doc_stats
)
SELECT doc_hash, topic, n
FROM ranked
WHERE rn <= 25
ORDER BY n DESC
LIMIT 330;
```

把结果落到 `pilot_docs.csv`，并在副本中建临时表 `pilot_docs(doc_hash TEXT PRIMARY KEY)` 后导入；计算 `SUM(n)`，若不在 4,500–5,500，按 `rn` 增减小批量文档后重算。

### 3.3 裁剪副本

只保留入选文档的 `source_documents` / `document_products`，清空题目与标签派生表；这是测试夹具，绝不能在生产库执行。以下 SQL 必须在同一个 SQLite 会话里执行（临时表 `pilot_docs` 不会跨连接保留）：

```sql
CREATE TEMP TABLE pilot_docs(doc_hash TEXT PRIMARY KEY);
-- 从 pilot_docs.csv 导入 doc_hash；下面的删除只作用于副本
DELETE FROM question_variants;
DELETE FROM canonical_dependents;
DELETE FROM merge_candidates;
DELETE FROM canonical_questions;
DELETE FROM questions;
DELETE FROM labels_staging;
DELETE FROM label_facts;
DELETE FROM golden_labels;
DELETE FROM document_events;
DELETE FROM document_products WHERE doc_hash NOT IN (SELECT doc_hash FROM pilot_docs);
DELETE FROM source_documents WHERE doc_hash NOT IN (SELECT doc_hash FROM pilot_docs);
UPDATE document_products SET extracted_at = NULL, indexed_at = NULL, questions_n = 0;
```

### 3.4 拷贝 MD 产物

按 `document_products.md_rel` 从生产 `20-题库MD` 复制到 `pilot\corpus\20-题库MD`，保持相对路径不变。源 PDF/docx 不需要复制：`extract.doc_pool()` 有 md 产物时优先用 md，`source_documents.src_path` 仍指向生产只读原件，G5 可核对存在性。

## 4. 配置入口

所有路径都用环境变量注入，不修改仓库默认值；PowerShell 7 示例：

```powershell
$env:KB_CORPUS_ROOT = 'D:\pilot\5000\corpus'
$env:KB_BUILD_DIR   = 'D:\pilot\5000\build'
$env:KB_DB          = 'D:\pilot\5000\build\kb.sqlite'
$env:KB_META_DIR    = '<REPO_ROOT>\meta'
$env:PYTHONUTF8     = '1'
$env:PYTHONIOENCODING = 'utf-8'
```

**推荐做法：只改一份 `D:\pilot\5000\config.json`**。`prepare` 首次运行会自动生成该文件；把 `llm.key` 填上后，`run --with-label` 即可用，不需要手工拼环境变量。脚本内部会按配置注入 `KB_*` 与 `LLM_*`。

| 配置入口 | 作用 | 本次值/说明 |
|---|---|---|
| `D:\pilot\5000\config.json` | 一键脚本的唯一配置 | `llm.key` 填 API key；其他路径已给默认值 |
| `KB_CORPUS_ROOT` | 语料根，决定 `20-题库MD`、收件箱、G5 路径 | `D:\pilot\5000\corpus` |
| `KB_BUILD_DIR` | 台账、影子库、日志、manifest | `D:\pilot\5000\build` |
| `KB_DB` | 本次事实源 | `...\build\kb.sqlite` |
| `KB_META_DIR` | 规则/标签词表，仍用仓库版本 | 仓库 `meta` |
| `KB_OCR_ENGINE_DIR` | 仅当本次触发 OCR 时使用 | 不触发 OCR 时可不设 |
| `LLM_PROVIDER` / `LLM_BASE` / `LLM_KEY` / `LLM_MODEL` | 仅打标冒烟用 | 不跑全量打标时可不设 |
| `LLM_CONCURRENCY` / `LLM_PRICE` / `LLM_JSON_MODE` | 打标并发/预算/JSON 模式 | 冒烟建议 `1` / 低预算 |
| `HF_ENDPOINT` | fastembed 模型下载镜像 | 默认已设 `https://hf-mirror.com` |

注意：`KB_BUILD_DIR` 必须与生产 build 分离；不要只改 `KB_DB` 而共用生产 `BUILD_DIR`，否则影子库、锁、manifest 会互相污染。

## 5. 执行链路

以下命令均在仓库根执行。推荐直接用一键脚本（先准备，再按需带打标）：

```powershell
# 1) 准备副本、按目标题数抽 121 文档、复制 MD（不需要 key）
python -m mianjing_kb.pilot5000 prepare --config D:\pilot\5000\config.json
# 2) 核心链路：extract → canonical → refresh → 检索冒烟
python -m mianjing_kb.pilot5000 run --config D:\pilot\5000\config.json
# 3) 填好 config.json 的 llm.key 后，追加 100 题打标冒烟
python -m mianjing_kb.pilot5000 run --config D:\pilot\5000\config.json --with-label
# 4) 汇总报告
python -m mianjing_kb.pilot5000 report --config D:\pilot\5000\config.json
```

也可以用 `kb pilot prepare|run|report` 或 `scripts\pilot5000.ps1`。下面是分步命令，便于排障。

### 5.1 预检

```powershell
kb status --json
kb extract --db $env:KB_DB --plan
kb extract --db $env:KB_DB --stats
```

`--plan/--stats` 是只读连接，不允许出现 `journal_mode` 变化。

### 5.2 抽取 5,000 题

```powershell
# 主试跑：保留真实分布，默认只跳过已知 review/fail
kb extract --db $env:KB_DB --limit 121

# 严格通过版本（可选）：只放行 gate=pass；题数不足时扩充样本
kb extract --db $env:KB_DB --limit 121 --require-gate
```

记录输出中的 `docs`、`questions`、`errors`、`qtype`、`conf`。首轮不要加 `--incremental`；增量验证放到第二轮。

若选样包含没有 gate 结论的文档，先用 `kb gate --audit` 补齐台账，或改用不过滤 gate 的主试跑；不要把 `--require-gate` 当默认。

### 5.3 增量安全回归

```powershell
kb extract --db $env:KB_DB --incremental
```

预期：`docs=0`、`skipped_unchanged=121`，且 `document_products.questions_n` 不被清零。

### 5.4 聚簇与建库

```powershell
kb canonical --db $env:KB_DB
kb refresh
```

`refresh` 会在 `KB_BUILD_DIR` 建 `面经库_shadow.db` 并跑 G1–G5/G8；门禁失败时不得切换，测试到此停止。

如果 `refresh` 自动 `copy_vec` 失败，允许在影子库上：

```powershell
kb refresh --reembed
```

但必须确认向量数 = 题数、`vec_meta.model = BAAI/bge-small-zh-v1.5`、`question_set_hash` 一致。

### 5.5 检索冒烟

```powershell
kb search "HashMap 扩容机制" --limit 5
kb search "MySQL 索引失效" --mode hybrid --limit 5
kb eval --queries eval/demo_queries.yaml --db "$env:KB_BUILD_DIR\面经库.db" --k 5 --mode hybrid
```

`eval` 的 demo 只用于确认检索没有完全退化；Golden 报告作为候选基线：
```powershell
kb eval --golden eval/golden_queries.yaml --db "$env:KB_BUILD_DIR\面经库.db" --k 10 --mode kw `
  --report "$env:KB_BUILD_DIR\golden_report.json"
```

### 5.6 打标冒烟（可选，100 题，key 就绪即可跑）

配置 `config.json` 的 `llm.key` 后，用一键入口追加：

```powershell
# 只跑打标，不重跑 extract/canonical/refresh
python -m mianjing_kb.pilot5000 label --config D:\pilot\5000\config.json
```

等价分步命令：

```powershell
kb label --check
kb label --dry-run --limit 100
```

只做 100 题冒烟，验证调用链、JSON 模式和非法枚举；**不要跑全量 5,000 打标**。标签 v2 的稳定 ID、闭集与 `topic/qtype/difficulty` 回填尚未合入生产，全量结果不可比。标签结构见 `docs/36`。

### 5.7 本轮实测（2026-11-19，未打标）

| 项 | 结果 |
|---|---|
| 选样 | 121 文档 / 估算 4,544 题（`seed=7`） |
| `extract` / `canonical` | 4,544 题 / 3,712 簇（耗时 4.9s / 0.4s） |
| `refresh --reembed` | **PASS**，`documents=118`、`questions=4,544`、`vectors=4,544`，G1–G8 PASS、G9 WARN，原子切换 |
| `post_check` | `quick_check=ok`，题/文档/向量计数一致 |
| 完整性 | `qkey_dup=0`、`orphan_variants=0`、`orphan_canonical=0` |
| Golden（kw，候选） | Recall@5 0.1591 / MRR@10 0.1250 / nDCG@10 0.1483 / 无答案误命中 0 |
| 打标 | 未跑（`llm.key` 为空）；填 key 后执行 `pilot5000 label` |

Golden 指标低于生产全量基线，主要因为 50 条 Golden 的预期 `q_key` 只有部分落在 121 文档切片内，**不能当作检索质量回退**；它只用于确认副本链路可跑通。

## 6. 校验清单

### 6.1 计数与身份

| 校验 | 期望 | 失败处理 |
|---|---|---|
| `questions` 行数 | 4,500–5,500 | 调整切片文档数后重跑 |
| `questions_n` 总和 | 与 `questions` 行数一致（允许 0 题文档差异单独解释） | 停止，检查 `products.upsert` |
| `(doc_hash,q_norm_hash)` 重复组 | 0（在 016 已应用的副本上） | 停止，检查 016/抽取去重 |
| `questions.q_key` 唯一 | 0 重复 | 停止 |
| `question_variants` | 与题行 1:1 或按 canonical 口径可解释 | 记录差异 |
| 孤儿 `canonical` / `variant` | 0 | 停止 |
| `document_products` 行 | 只含入选 121 文档 + 必要的 source/orphan | 记录 |

### 6.2 门禁与向量

| 校验 | 期望 |
|---|---|
| `refresh` G1/G2/G3/G4/G5/G8 | 全 PASS；G3 允许按样本规模解释 WARN |
| `PRAGMA quick_check` | `ok` |
| `vec_questions` 行数 | = `questions` 行数 |
| 向量维度 | 512 |
| `vec_meta.model` | `BAAI/bge-small-zh-v1.5` |
| `vec_meta.question_set_hash` | 与 `embed_questions.question_set_hash()` 一致 |
| `shadow_publish.json` | 存在、`publishable=true`、`gate_verdict=PASS`；仅对当前 shadow 有效 |

### 6.3 质量抽检

- 随机抽 50 题人工看：题干/答案是否对应、是否截断、是否重复；
- 按 topic 统计覆盖，至少覆盖 8 个一级领域；
- 空答案率、答案 <20 字占比与生产基线对比，偏差 >10 个百分点要解释；
- qtype 分布不得单类 >85%；
- 检索 10 条 demo query，hit@5 不低于 0.7（仅冒烟门槛）；
- 打标冒烟 100 题：非法枚举 0，`review_state=pending` 比例记录。

### 6.4 运行与资源

- 记录每阶段 `elapsed_sec`、峰值内存、build 目录大小；
- 记录锁是否被正确释放：`kb status --json` 中 `kb.lock`/`online.lock` 不应显示 ACTIVE；
- 记录 `extract`/`canonical`/`refresh` 的非零退出码；任何非零都要写入报告，不能只写“基本成功”。

## 7. 停止与回滚

出现以下任一情况立即停止，不进入下一阶段：

1. 生产库 `schema_version` 与预期不一致，或测试过程中被自动迁移；
2. 生产库/线上 `面经库.db` 被任何命令写入；
3. `quick_check` 失败，或 G1–G5/G8 任一硬门禁 FAIL；
4. 题数偏离 4,500–5,500 超过 15%，且无法用切片解释；
5. `questions_n` 与题行不一致、`q_key`/`q_norm_hash` 出现不可解释重复；
6. 向量数与题数不一致、维度不是 512、`question_set_hash` 不一致；
7. 写锁未释放，或出现 `LockHeld`；
8. 打标非法枚举 >2%，或标签字段与 `docs/36` 的闭集不一致。

回滚方式：整个 `D:\pilot\5000` 目录删除；生产库和线上检索库均未参与写入，不需要反向 SQL。若在影子库上执行过 `refresh`，只保留 `pilot\5000\build\rollback` 供分析，不回写生产。

## 9. 建议的下一步

1. 先按本方案在副本跑一轮 5,000 题，不跑全量打标；
2. 同时完成 D-27 的生产 `schema_version` 核对和 016/qnorm 预演；

## 2. P1 详情

### CR-01 URL 脱敏回归

**复现**（修复前）：

```text
redact("见 https://user:pass@host/path?token=abc&x=1 和 me@example.com")
→ ('见 https://user:pass@host/path?token=abc&x=1 和 [联系方式]', True)
```

原实现为了保留技术上下文，把 URL 整体从遮罩列表移除，导致带凭据/签名参数的 URL 原样进入 LLM 请求。技术文档 URL 应保留，但凭据不能保留。

**修复**：新增 `_sanitize_url()`，保留 scheme/host/path/普通 query，去掉 `user:pass@`，把 `token/api_key/secret/sign/signature/password/session/...` 的值替换为 `REDACTED`；无敏感内容时原样返回，不改变 URL 编码。

**回归**：`test_redact_url_keeps_path_but_strips_credentials_and_token`，同时保留 `https://blog.example.com/post?x=a%2Fb` 原样。

### CR-02 disagree 行阻断整批 merge

**复现**（修复前）：

```text
questions: 1='#include <stdio.h>', 2='什么是虚函数?'
staging:   1=disagree(C++/八股), 2=agree(C++/八股)
assess → {'ok': False, 'fails': ['code_fragment=1'], 'staged': 2}
```

`disagree` 行本来就会在 merge 中单独 hold，不参与合并；但它仍被 `assess` 计入碎片统计，导致一条人工分歧把整批正常标签卡死。

**修复**：`assess` 的 SQL 增加 `WHERE s.review_state IS NOT 'disagree'`；`pending` 仍然参与并硬拦。

**回归**：`test_quality_ignores_disagree_rows`。

### CR-03 碎片跳过无可审计清单

`pick_targets(skip_code=True)` 只返回 `skipped_code` 计数，没有 qid。生产 20,010 题命中 78 条、试跑 4,544 题命中 175 条，其中存在“假设已有函数 `int recv(char*, int);`”这类可能误杀的题干；只给数字无法复核。

**修复**：`stats["skipped_code_rows"]` 保存 qid + q_text；`run_batch` 写 `label_skipped_code.jsonl`，q_text 先走 `redact()` 再截 300 字，保留技术语义、去掉个人信息。

**回归**：`test_run_batch_records_skipped_code_qids`。

## 3. P2/P3 说明

### CR-06 小批次 `其他` 率可绕过

`assess` 当前：

```python
if n >= min_batch and other_rate > other_hard:
    fails.append(...)
elif other_rate > other_warn:
    warns.append(...)
```

`min_batch=20`。一个 10 题批次全部判“其他”时 `n=10`，只得到 WARN，`ok=True`，仍可 merge。对试跑/小批量，这正是最需要拦的场景。

建议二选一：

1. 增加 `--strict-quality`，开启后 `n < min_batch` 也按 `other_hard` 硬拦；
2. 把 `min_batch` 降到 5，并保留 1–4 条批次的 WARN。

不建议直接把 `min_batch` 设为 1：单题“其他”会阻断所有试跑。

### CR-07 结构合法 ≠ 标签正确

30 条审核里 `issues` 全部为空，但 14 条建议改 `topic/qtype/difficulty`。`validate_label` 只检查枚举、长度、范围；`label_quality` 只检查碎片/pending/主题率。两者都发现不了：

- `216295` 数据结构题被判“其他”（规则里已有“数据结构→算法”）；
- `216108/216083` 行为题被判“八股”；
- 碎片被模型合理化出 canonical_q。

这不是加一条正则能解决的，需要金标集/混淆矩阵（`g6b_golden`）或固定抽样人工复核；门禁只能保证“不把已知坏样本 merge”，不能保证“标签语义正确”。

### CR-08 全量取回再切片

`pick_targets` 为支持 `skip_code`，把 SQL `LIMIT` 改成取全表再 Python 切片。当前 20k 题内存可接受；若题库到十万级，每次 `--limit 100` 也会加载全部 TODO 行。建议：

- `skip_code=False` 时保留 SQL `LIMIT`；
- `skip_code=True` 时用 `fetchmany` 分批扫描，凑够 `limit` 即停。

### CR-09 跳过清单覆盖写

`label_skipped_code.jsonl` 用 `"w"`，每次 run_batch 覆盖。跨批次审计需要保留历史时，建议改为按日期/批次命名，或 append 并带 `run_id`。

### CR-10 prompt 上下文不足

`label_one` 仍是 `q_text[:300] + a_text[:300]`，没有 `file_name/source_topic` 和前后题。30 条中产品/业务题被判“其他”、以及“资源/方法/产品之外”三连问，都和上下文缺失有关。建议在 prompt 中加来源文件名、source_topic、同文档前后各一题（脱敏后），而不是只扩字数。

### CR-11 trace 频繁 open

`run_batch` 每成功一题 `open("a")` 一次；2 万题约 2 万次打开/关闭。建议在 `run_batch` 生命周期内保持一个 trace 句柄，退出时 flush/close；失败清单同理。

### CR-12 fragment token

`_sanitize_url` 处理了 query，但没有处理 `#token=...`。若签名放在 fragment，仍会保留。

2026-11-25 已修复：query 与 fragment 共用敏感参数清洗，覆盖 `#access_token=...` 和
`#/callback?signature=...`；普通 fragment（如 `#installation?x=...`）原样保留。聚焦复审后
又补齐大写 scheme、非法 IPv6 URL、`oauth_token`、英文逗号相邻 URL、合法逗号路径、`;`/
`&amp;` 分隔符及 fragment `?` 前缀等边界。回归见 `tests/test_llm_client.py` 的
`test_redact_url_*` 与 `test_redact_malformed_url_does_not_return_secret_verbatim`。

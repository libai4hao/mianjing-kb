# 文档索引与版本规则（docs/README.md）

> 本页是 `docs/` 的**唯一目录入口**。每份文档顶部都标了「状态 / 最后实质更新 / 适用方案版本」，
> 三者与本页冲突时**以本页 + 代码为准**，并应回改文档。

## 一、三条规则（先记住这三条，再读文件）

1. **当前口径只有一个入口**：`docs/32-当前口径总表-2026-11-19.md`（方案 / 门禁 / 阈值 / 基线 / 稳定键 / 未实现清单）。
   R1/R2/R3 均已移入 `docs/archive/`，只作版本演进留痕，**不得作为执行依据**。
2. **流程只有一份现状描述**：`docs/19-功能流程图.md`（Mermaid，随源码走）。
   其他文档里的"流水线 / 状态机"文字属**设计意图**，与 19 不一致时以 19 + 代码为准。
3. **数字只有一份现行基线**：`docs/29-数据基线与统计口径-2026-11-19.md`。
   旧文档里出现的 `18,642 / 32,087 / 41,673 / 13,182` 等数字**属于不同时点、不同口径**，
   引用时必须带"时点 + 定义"，否则视为无效引用（对照表见 29 §2）。

## 四、新增文档的规矩

1. 编号递增，文件名带日期（`NN-主题-YYYY-MM-DD.md`）；一旦被取代，移到 `docs/archive/` 并在本页状态表更新。
2. 顶部必须有：`> 状态：现行 / 历史 / 一次性报告 · 最后更新：YYYY-MM-DD · 适用版本：v2-R3 / 无`。
3. 只描述现状的文档引用 `19`；只描述数字的引用 `29`；不再新写"另一套流程文字"。
4. 改了基线数字、改了门禁判据、改了阶段划分，三件事必须同一次提交：改代码 / 改 `19` 或 `29` / 回填 `待办清单`。

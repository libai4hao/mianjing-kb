## 三、批次一逐项设计

### F1 打标事实源与 qid 解耦（B1，P0）

**问题**：见 §1.1 B1。qid 漂移使打标（花钱买来的数据）在任何一次全量重 extract 后清零且无告警。

**设计**：新增 `label_facts` 表作打标事实源，键用 `q_norm_hash`（extract 已算好，`tools/extract.py:124`；同文题共享 hash，重挂语义=同文题打标一致，与 canonical 同题簇同理）。

1. 新迁移 `meta/schema/007_label_facts.sql`：

```sql
-- 007：打标事实源（跨 extract 重切存活）——修复审核报告 B1
-- merge 时按 q_norm_hash 落档；extract 重切后按 q_norm_hash 重挂。
CREATE TABLE IF NOT EXISTS label_facts (
  q_norm_hash TEXT PRIMARY KEY,   -- sha256(归一化题干)[:16]（extract.py:124）
  topic       TEXT NOT NULL,
  qtype       TEXT,
  difficulty  INTEGER,
  tags        TEXT,               -- JSON 数组字符串
  merged_at   TEXT NOT NULL
);
```

2. `tools/kb/db.py`：`migrate()` 末尾追加 `_ensure_label_facts(conn)`——executescript 007 + 三个 `_column_exists` 守卫的 ALTER：
   - `labels_staging ADD COLUMN q_norm_hash TEXT`（新打标行带上，供 merge 校验）
   - `questions ADD COLUMN difficulty INTEGER`、`questions ADD COLUMN tags TEXT`（F9 落库用）

3. `tools/batch_label.py`：`pick_targets` SELECT 加 `q.q_norm_hash`（:52-56）；`label_one` 行加 `"q_norm_hash": q["q_norm_hash"]`（:70-75）；`write_staging` 列清单同步（:79-84）。

4. `tools/extract.py` `store()`（:131-140）：INSERT 后按 q_norm_hash 重挂：

```python
# B1 修复：重切后按 q_norm_hash 重挂已 merge 的打标（label_facts，007）
conn.execute(
    "UPDATE questions SET "
    " topic=(SELECT lf.topic FROM label_facts lf WHERE lf.q_norm_hash=questions.q_norm_hash), "
    " qtype=COALESCE((SELECT lf.qtype FROM label_facts lf WHERE lf.q_norm_hash=questions.q_norm_hash), qtype), "
    " difficulty=(SELECT lf.difficulty FROM label_facts lf WHERE lf.q_norm_hash=questions.q_norm_hash), "
    " tags=(SELECT lf.tags FROM label_facts lf WHERE lf.q_norm_hash=questions.q_norm_hash) "
    "WHERE doc_hash=? AND q_norm_hash IN (SELECT q_norm_hash FROM label_facts)", (doc_hash,))
```

`main()` 输出统计加 `label_reattached`（重挂数）与 `label_facts_lost`（label_facts 里 q_norm_hash 已不在 questions 的行数——即重切后真正丢失的打标，>0 时 stderr 打 warn）。

**测试**：`test_extract.py` 重切同题（同 q_norm_hash、新 qid）→ topic/难度重挂；`test_batch_label.py` merge 后 label_facts 有对应行。

**问题**：UPDATE 无空值守卫（bug2）；qtype/difficulty/tags 丢弃（bug3）；staging 跨 extract 残留行被静默清（B1 加重项）。

**设计**：`tools/batch_label.py` `merge()`（:170-188）在 G6 通过后：

```python
# F6：孤儿行校验——qid 已失效或题干已变的 staging 行拒绝 merge（防跨 extract 残留）

    "SELECT COUNT(*) FROM labels_staging s LEFT JOIN questions q ON q.qid=s.qid "

            "note": "staging 存在跨 extract 残留行，拒绝 merge——重跑打标或人工清理 staging"}
# F9+F3：四列落库，topic/qtype 空值不覆盖已有值
conn.execute(
    "UPDATE questions SET "
    " topic=COALESCE(NULLIF((SELECT s.topic FROM labels_staging s WHERE s.qid=questions.qid),''), topic), "
    " qtype=COALESCE((SELECT s.qtype FROM labels_staging s WHERE s.qid=questions.qid), qtype), "
    " difficulty=(SELECT s.difficulty FROM labels_staging s WHERE s.qid=questions.qid), "
    " tags=(SELECT s.tags FROM labels_staging s WHERE s.qid=questions.qid) "
    "WHERE qid IN (SELECT qid FROM labels_staging)")
# F1：打标事实落档（同事务）
conn.execute(
    "INSERT OR REPLACE INTO label_facts "
    "SELECT q.q_norm_hash, s.topic, s.qtype, s.difficulty, s.tags, ? "
    "FROM labels_staging s JOIN questions q ON q.qid=s.qid WHERE COALESCE(s.topic,'')!=''",
```

### F7 同路径内容变更 → 旧行退役（报告二幽灵行）

**问题**：见 §1.4。一次原地编辑 = 台账幽灵行 + 检索库同内容双份题，全链门禁无一道能发现。

**设计**：`tools/intake.py` 新增（main() 在 `action in ("added","quarantined")` 且非 dry-run 时、落新行前调用）：

```python
def retire_path_ghost(conn, rel: str, new_hash: str) -> int:
    """同物理路径已被新内容取代：旧占用行退役 superseded（note 记 replaced_by）。

    幽灵行修复（审核报告二 §二）：intake 按 hash 判重，同路径原地改内容会插新行、
    旧行仍 classified 且 src_path 指向同一文件——G5 只查路径存在拦不住，
    extract 会对同一物理文件按两个 doc_hash 各抽一份题。
    absent/superseded 不退役（absent 行本就等 resurrected 复活）。
    """
    rows = conn.execute(
        "SELECT doc_hash FROM source_documents "
        "WHERE dir_path=? AND file_name=? AND doc_hash!=? "
        "  AND status NOT IN ('absent','superseded')",
        (dir_of(rel), Path(rel).name, new_hash)).fetchall()
    for r in rows:
        conn.execute("UPDATE source_documents SET status='superseded', note=? WHERE doc_hash=?",
                     (f"replaced_by:{new_hash}", r["doc_hash"]))
    return len(rows)
```

- 输出统计加 `retired_ghosts`；superseded 可经 review_cli 恢复（`RESOLVABLE` 含 superseded），误退役可人工撤销。
- 99 区（quarantined）rel 与正式区 rel 不同，不会误伤正式区行。

**测试**：classified 行 + 同路径新 hash → 旧行 superseded+note、新行 added；absent 行不退役。

## 五、风险与回滚

- **007 迁移纯增量**（新表 + ADD COLUMN），不动存量数据；回滚 = git revert，残留空列/空表无害。
- **merge 行为变化**：孤儿行拒绝是新增拦截；历史 staging 行 q_norm_hash 为 NULL 放行（qid 对得上即可），不卡现有流程。
- **copy_vec 拒绝拷贝**：只在确实错位时触发，触发时本就该 `--reembed`（历史记录亦如此）。
- **intake 退役**：superseded 可经 review_cli 人工恢复；dry-run 不退役。
- 全部改动不直接触碰检索库与线上数据；行为变化在下次重跑对应工具时生效。
- 每项独立提交（沿用仓库 conventional commit 中文风格），可单独 revert。

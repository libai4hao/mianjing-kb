  属于索引结构变更，必须走"新表 + 影子库 + G4 校验 + 原子切换"，不能在 review 批次里做。
- 验收：带 `--topic` 的 vec 查询在 k=10 时稳定返回 10 条；`verify_ledger` G4 对新表同样生效。

## 四、2026-11-19 三轮 review 新增未做项

### T11 【未做】intake 单一大事务分块

- 现状：全批写入最后统一 commit，30 分钟扫描中途崩溃会整批丢失，且全程持有写锁。
- 已做的替代：入口先 `db.backup_db()` 热备份；批次号秒级+随机，`record_batch` 冲突不再覆盖。
- 待做：每 N 条（建议 500）commit 一次，批次状态标 `in_progress`，崩溃后可续扫；或把取舍写进 SOP 并明确"失败整批重扫"。
- 验收：模拟中途异常后，已登记行可查、批次状态可区分、不出现半条记录。

### T12 【未做】note 结构化（事件表 / JSON）

- 现状：`converted_to:` / `replaced_by:` / `needs_convert` / `moved_from:` 全靠子串解析，note 只增不减。
- 待做：单独 `document_events(doc_hash, kind, payload_json, at)` 事件表，或 note 改结构化 JSON；旧子串解析保留只读兼容一层。
- 验收：doc_convert / intake / review_cli / verify 不再新增子串依赖；旧行可迁移。

### T13 【未做】状态常量收口 `kb/status.py`

- 现状：`classified` / `superseded` / `quarantined` / `absent` 散落在 intake、purge、classify、verify、doc_convert。
- 待做：`INGESTED` / `RETIRED` / `QUARANTINED` / `RESERVED` 分组常量，各工具共用；`OK_STATUS` 不再各写一份。
- 验收：状态字符串只在 `kb/status.py` 出现；新增状态有单测。

### T14 【未做】迁移脚本事务化 + 并发保护

- 现状：含 `executescript` 的迁移会隐式 commit，普通 `execute` DDL 不 commit；多进程同时 `migrate()` 没有锁内二次校验。
- 已做的替代：009 改逐列幂等 + 迁移末尾 `_validate_schema()` 收尾校验；全新库/增量库 schema 一致性有测试。
- 待做：纯 execute 迁移包 `BEGIN IMMEDIATE`；executescript 拆成逐句执行或用幂等脚本；版本表在锁内二次校验。
- 验收：并发两个进程跑 migrate 均安全；注入中途失败后可续跑且不缺列。

### T15 【未做】跨进程写锁（intake / batch_label / purge）

- 现状：refresh.py 已有 `refresh.lock`；intake、batch_label、purge 之间仍可能同时写 kb.sqlite
  （已加 `busy_timeout=10000` + `synchronous=FULL`，但长任务仍可能互相等锁超时）。
- 待做：写库工具统一锁文件（PID + 启动时间），拿不到锁直接退出并提示正在运行的进程。
- 验收：两个写库工具并发启动，第二个明确拒绝而不是 `database is locked` 栈。

### T16 【未做】Word 单文件转换超时

- 现状：`doc_convert` 用 `DispatchEx` 隔离 + 失败重开实例，但 COM 调用没有可靠进程级超时；卡住的文档会阻塞整批。
- 待做：独立子进程 + watchdog（超时 kill 子进程并记 `timeout`），或按文件拆分调用。
- 验收：注入一个永不返回的 fake Word，整批在限定时间内继续下一件并记录失败。

### T17 【未做】`convert_one.py` 纳入版本管理

- 现状：转换主逻辑仍在语料目录 `21-面经数据库/tools/convert_one.py`，不受 git 管理；本轮只把路径/sha256/
  pymupdf4llm 版本写进 reconvert 日志。
- 待做：迁入 `tools/kb/convert_one.py`（或 vendor 固定版本），reconvert 优先用仓内版本，语料侧仅作 fallback。
- 验收：换机器不配语料侧 tools 也能跑转换；哈希与日志可回归。

### T18 【待定口径】G4 WARN 与"硬门必须 PASS"

- 现状：`g4_index` 在 `vec_questions` 未建或 sqlite_vec 不可加载时返回 `WARN`（向量层可选）；refresh 硬门因此
  拒绝 `FAIL/SKIP/未知`，但放行 `WARN`。评审建议"硬门必须 PASS"。
- 待定：要么承认向量层可选（保持 WARN），要么把 G4 改硬失败并同步 refresh / docs/15；二选一前不单侧收紧。
- 验收：docs/15 与 refresh `check_gates` 口径一致，G4 无 vec 场景有明确测试。

### T19 【未做】历史 `converted_to:` 裸格式校验

- 现状：G5 只校验新格式 `converted_to:<dir>/<name>#<hash>`；历史行 `converted_to:x.docx` 直接跳过，
  仍可能出现"原 .doc 已退役、docx 未入库"。
- 待做：一次性盘点历史 superseded 行，按文件名回填目录+哈希，或提供 `--legacy-converted` 审计模式。
- 验收：全库 superseded 行的 `converted_to` 都能解析到有效后继记录。

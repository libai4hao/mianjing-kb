## 一、结构级（需要迁移 + 影子重建）

### T1 向量表加 metadata，检索过滤下沉到 KNN

- 现状：`vec_questions` 只有 `qid + embedding`，`search --mode vec` 先 KNN 取 k 再 `AND q.topic=?`，带过滤时召回不足；`classify --vec` 同样。
- 为什么没顺手改：要改成 `vec0(embedding float[512], topic text, qtype text)` 并重建 **18,642 条向量**，
  属于索引结构变更，必须走"新表 + 影子库 + G4 校验 + 原子切换"，不能在 review 批次里做。
- 验收：带 `--topic` 的 vec 查询在 k=10 时稳定返回 10 条；`verify_ledger` G4 对新表同样生效。
- 建议批次：与下一次 `refresh.py --reembed` 合并做。

### T2 迁移版本化 + schema 单一来源

- 现状：`db.connect()` 每次调用都执行 9 段 DDL；`002_parent_dir.sql` / `009_review_columns.sql` 与
  `kb/db.py` 内联副本双写；`006`（题级 topic）只有代码没有文件。
- 为什么没顺手改：要动 `connect()` 的每一次调用（30+ 处），风险与收益不对等；且 002 的视图定义已经在代码里
  演进过一次，贸然换成"只跑文件"会让新旧库分叉。
- 验收：新库首连只执行一次 DDL（可用 `PRAGMA user_version` 断言）；002/009 删内联副本后全量测试仍绿；
  补 `006_question_topic.sql`。
- 建议批次：下次结构升级时一并做，先写 `schema_migrations` 表 + 幂等脚本。

### T3 包化与入口收敛

- 现状：16 个脚本各自复制 `if __package__ in (None, ""): sys.path.insert(...)`；`kb` 与 `tools.kb` 双路径
  靠 `kb/__init__.py` 的 `setdefault` 兜；无 `pyproject.toml`，无法 `pip install -e .`。
- 为什么没顺手改：会动全部脚本的 import 头，且 `scripts/` 里的 ps1 也依赖当前布局；需一次性切换 + 回归。
- 验收：`python -m mianjing_kb.pipeline --check` 可跑；测试里不再需要 `sys.path.insert`；`pyflakes` 仍 0 告警。

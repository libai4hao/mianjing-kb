## 3. 技术路线检查

### 3.1 链路完整性（全通，13,296 题端到端可检索）

```
intake(bookmarks/inventory) → classify(+overrides) → convert/reconvert → gate
  → dispatch(6路由) → OCR(ocr_pages/ocr_merge) → extract(chunker v2)
```

### 3.2 发现的结构性问题（按优先级）

## 4. LLM 本地选型推荐（P3-④ / 06-R3 待决 #2）

硬件前提：i5-13400F + 32GB RAM + **RX 6650XT 8GB（AMD，无 CUDA）** → 走 Vulkan（Ollama/llama.cpp 对 AMD 成熟）。

| 方案 | 显存占用 | 预期速度 | 中文能力 | RAG 适配 | 结论 |
|---|---|---|---|---|---|
| **Ollama + Qwen3-8B (Q4_K_M)** | ~5.2GB，8GB 卡余量舒适 | ~40-60 tok/s | 强 | OpenAI 兼容 API，零耦合 | **首选** |
| Ollama + GLM-4-9B-Chat (Q4) | ~5.8GB，上下文余量小 | ~35-50 tok/s | 强（智谱生态） | 同上 | 备选（生态偏好时） |
| Qwen3-14B (Q4, 部分层 offload) | 8GB + CPU 分担 | ~10-15 tok/s | 更强 | 同上 | 质量优先再上 |
| DeepSeek-R1-Distill 系 | — | 推理链长，延迟高 | — | RAG 问答不合适 | 不建议 |
| 云端 API | — | — | — | — | 留作 fallback（智谱/豆包折扣 API） |

**推荐结论：先 Ollama + Qwen3-8B 冒烟验证**（下载 ~4.7GB），用 20 题「结构化抽取 + RAG 问答」双盲测对比 GLM-4-9B（ollama 拉 gguf 即可），半天出结论——即 06-R3 待决 #2 的「0.5 天验证」方案。部署形态 `ollama serve`（11434），P3-④ 走 OpenAI 兼容客户端，未来切云端不改代码。

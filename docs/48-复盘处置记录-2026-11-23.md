## 2 P0-3 切题回归基线（新增 `mianjing_kb.chunk_regress`）

问题：7 天 18 次 `fix(chunker)`，没有可比基线，只能全量重跑看总数；盲重跑还出过 36,515 题的反例。

做法：固定 20 个 `doc_hash`（8 目录噪声 / 6 切块错位 / 6 正常，`eval/chunk_regress/docs.txt`，
**只存 hash 不存原文**），每篇计量四项：题数、空答案、弱题（不满足 `_heading_questionish`
的题，即标题/碎句被当题）、probe 数。

```
python -m mianjing_kb.chunk_regress --check     # 改 chunker 后先跑，超容差即 FAIL
python -m mianjing_kb.chunk_regress --make      # 有意改变行为后重建基线
```

容差：单篇题数 ±5%，总题数 ±2%，空答案 ±2%，弱题只许减不许增。

基线（`eval/chunk_regress/baseline.json`）：**20 篇 / 9,858 题 / 空答案 1,524 / 弱题 477 / probe 28**。
同环境复跑 `--check` → `[pass]`。测试 `tests/test_chunk_regress.py` 覆盖计量、题数跳变、弱题增长、镜像缺失四种判定。

## 6 补答 pilot（P0-1 的决策数据，50 条）

口径：30 条 `boundary_gap`（切块错位）+ 20 条 `no_answer_source`（来源只列问题），本地 `qwen3-8b`，
逐题生成答案，产物在 `<BUILD_DIR>/pilot-answer-50/`（含原文，仅本机，不入库）。

| 指标 | 结果 |
|---|---|
| 耗时 | 50 题 37.5 s（≈0.75 s/题，模型常驻后） |
| 拒答 | 12/50（输出 `NO_ANSWER`） |
| 答案长度 | 最短 9 / 中位 53 / 最长 94 字 |
| 质量观感 | 大量答案停在"定义 + 一句注意事项"，**对残缺题干（题号串、半句、多个问题粘连）只能给泛泛作答** |

结论（建议）：**不做全量 5,216 条 LLM 补答**。理由是这批缺答案的题里，多数题干本身就残缺或不是题
（`boundary_gap` 的根因是切块错位，`no_answer_source` 的根因是素材只有问题清单），模型补出来的是
"看起来像答案"的通用句子，会污染可背内容，比空着更糟。正确顺序是先把切块修对（§2 的回归基线已就位），
剩下的 `no_answer_source` 保留空答案并如实标注。

同一 pilot 的 `review.md` 留给人工复核：若抽查发现 ≥60% 可直接背，则推翻上述建议改为分批补答。

## 7 打标 60 条探针（新词表 + 新 prompt 的抽样口径）

为验证"补词表后普通批次能不能落到 25% 线内"，随机取 60 条待打标题跑一轮（`kb label --limit 60`，
qwen3-8b，203 s ≈3.4 s/题，跳过代码碎片 3,376 行）：

| 指标 | 结果 |
|---|---|
| 产出 | 60/60，失败 0 |
| 词表外 topic | 8 条（被兜底改写 `其他` + `pending`，多为"数据库/缓存/微服务"这类上位词） |
| `其他` 数 / 率 | 10 / **16.7%**（门槛 25% FAIL、15% WARN） |
| 代码碎片 | 0 |

结论：普通批次 `other_topic_rate` 已从 `docs/45` 的 34.55% 降到 **16.7%**，过 25% 线、仍在 15% WARN 线上；
卡合并的只剩 `pending_review=8`，全部是"上位词"问题（`docs/47` P1-3）。这 8 条正是 P1-3 的样本，
先定上位词口径，再决定是否 `--merge`。探针跑完即清 staging（60 行），生产标签仍是 36 条。

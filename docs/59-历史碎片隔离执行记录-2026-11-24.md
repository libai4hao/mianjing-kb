# 历史碎片隔离执行记录（2026-11-24）

接 docs/58 §4：历史未标的 2,744 行里，2,656 行是被打标质量规则拦下的碎片。处置口径定为**隔离保留**，不是删除。

## 1. 隔离清单怎么来的

`build/label_skipped_code.jsonl` 会被后续批次覆盖（新题残余那轮把它改写成 45 行），所以清单不能依赖该文件，改为**用同一套谓词从现库重算**：

```python
code_reason = code_fragment_reason(q_text)
flags = deterministic_quality_flags(q_text, a_text)
hold = code_reason or ";".join(sorted(manual_review_flags(flags)))
skip = is_code_fragment(q_text) or hold
```

范围限 `qid<=216077` 且仍未打标。复算结果 **2,656 条**，与上一轮 `skipped_code=2656` 完全一致，说明判定可复现。

原因分布（合计 2,656）：

| 原因 | 条数 |
| --- | --- |
| 多题混杂 | 2,493 |
| call / assignment / control / return / declaration 等代码形态 | 93 |
| legacy_code_fragment（纯代码行判定） | 38 |
| 残缺 | 22 |
| 答案错配 | 7 |
| 多题混杂;残缺 | 1 |
| preprocessor / comment / condition | 6 |

主因是**多题混杂**：一个 chunk 里挤着多道编号问题或追问，当作单题会污染检索，不是 OCR 噪声那么简单。

## 2. 隔离动作

`build/ops/quarantine_apply.py`（`--apply` 才写库），单事务：

1. 建 `question_noise`（`questions` 同构 24 列 + `reason` + `quarantined_at` + `quarantined_by`）；
2. 逐行复制进 `question_noise`，再 `DELETE FROM questions WHERE qid IN (SELECT qid FROM question_noise)`；
3. `label_facts` 以 `q_norm_hash` 为键，删除后会变孤儿——命中的 **34 条** facts 复制到 `label_facts_noise` 后再从 `label_facts` 移除，审计信息不丢。

执行结果：`moved 2656, moved_facts 34, questions_left 18987, integrity ok`。

## 3. 一个必须回退的副作用：空文档

第一次 `refresh --reembed` 被门禁拦下：`md_zero_questions`。原因是有 27 篇文档的**全部**题目都是碎片，隔离后文档变成 0 题，文档↔题的可追溯性断掉。

处理不是放宽门禁，而是把"整篇只剩 0 题"的行退回：`quarantine_restore_empty_docs.py` 只退 `doc_hash` 下已无任何题的行，共 **28 条**，同时把对应 facts 从 `label_facts_noise` 退回。隔离净结果 **2,628 条**，`questions` 19,015。

这 28 条保持未标，作为文档存续的锚点；它们本身仍是碎片，不参与标签统计。

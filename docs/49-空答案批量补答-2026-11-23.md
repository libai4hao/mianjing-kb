# 49 · 空答案批量补答（本地模型，留痕可回滚）— 2026-11-23

> 状态：现行 · 最后更新：2026-11-25 · 适用版本：v2-R3

`docs/48` §6 的 pilot 建议"不补"，实际拍板是**先补答再打标**——顺序有道理：打标 prompt 会读答案片段，
答案空着时 topic/tags 只能靠题干猜。本篇记补答的口径、留痕与回滚，不粉饰质量风险。

## 1 口径

- 目标：`TRIM(a_text)=''` 且 `COALESCE(answer_source,'') IN ('', 'llm_error')`，且 `answer_state` ∈
  `boundary_gap / no_answer_source / ok`；**排除 `toc_noise`**（目录伪题不是题，补出来的只是噪音）。
  历史遗留的 `llm_error` 允许重试。
- 题干可见字符 < 6 的跳过（`skipped_short`），不送模型。
- 模型：本地 `qwen3-8b`（回环，内容不出本机）；输出 `NO_ANSWER` 的题**不写正文**，记 `llm_refused`，下轮不再重试。
- 写回：`a_text` + `answer_source='llm'` + `answer_model` + `answered_at`。
  `answer_state` **不改**——它记的是"原文有没有答案"的结构事实，补答不能把它洗成 `ok`。

## 2 迁移 019（`answer_source`）

`questions` 加三列：`answer_source`（`''`/`llm`/`llm_refused`/`llm_error`）、`answer_model`、`answered_at`。
目的只有一个：任何一次抽检都能一条 SQL 分清"原文答案"和"模型补的答案"：

```sql
SELECT answer_source, COUNT(*) FROM questions GROUP BY 1;
```

`kb status` 增加「补答 llm N 拒答 M」一行（老库没这列时自动省略）。

## 3 工具与断点续跑

```powershell
python -m mianjing_kb.answer_backfill --stats                  # 还剩多少、分布
python -m mianjing_kb.answer_backfill --limit 300 --concurrency 4            # 试跑不写库
python -m mianjing_kb.answer_backfill --concurrency 8 --apply                 # 全量写库
```

- 不带 `--apply` 的预览默认只跑 20 条；`--limit 0` 表示不限制，负数拒绝。预览与 `--stats` 只读、不拿写锁。
- `--apply` 在目标库父目录的 `kb.lock` 内覆盖选题、模型调用和写回；每 50 条提交一次，但写锁贯穿整批，
  期间不要并行运行 `extract` 等其他写库工具。进程被杀只丢最后不足 50 条，重跑自动跳过已留痕的题。
- 单条模型/服务失败不落库，保留空答案下次重试；写回时若 qid、题干、空答案或来源守卫已变化，
  计 `guard_skipped` + `error`，不覆盖也不虚报成功。
- 实测吞吐：`concurrency=4` 约 **1.04 s/题**，`concurrency=8` 约 **0.92 s/题**（本地单模型基本串行，
  并发只摊网络与解析开销）。

## 4 质量：先看清再接受

20 条抽样（写入后原样看正文）的典型形态：

| 形态 | 例子 | 判断 |
|---|---|---|
| 题干完整、模型有知识 | "写时复制的线程安全 list 怎么做" → 不可变对象 + 复制 + 并发/性能/内存考量 | 可用 |
| 题干被截断一半 | "DISTINCT 在所有列上转换为 GROUP BY…SELECT DISTINCT t1.a FR" → "使用 LIMIT 50" | 错，需人工修 |
| 不是题（版式/流程行） | "面试形式：一对一" → 一段"一对一面试通常指…" | 该拒答而没拒 |

因此本批补答的定位是**"有文本可检索"**，不是"可直接背"：`answer_source=llm` 的题在抽检里按
"需复核"处理，不计入"原文答案"的准确率口径。真要背，仍走人工校对。

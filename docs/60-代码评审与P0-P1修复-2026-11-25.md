## 4 canonical 链式误合治理（代表题星形挂靠）

问题根因是 `question_freq.cluster()` 对相似边直接做 DSU 两两 union：A~B、B~C 即使 A 与 C 不相似，
也会形成传递闭包。`report.build_clusters()` 与 canonical 全量重建共用这条路径，因此只改落库层无效。

落地口径：

- 保留唯一文本聚合、前缀倒排、完整 Jaccard 复核和 F6 短题拉丁实体闸门；`cluster()` 签名与 `DSU`
  返回类型不变，`max_dist` 继续兼容保留。
- 在相似图连通分量内选**直接覆盖的成员出现次数最多**的代表题；同分时依次比较自身出现次数、文本长度和最早位置。
  只把与代表题直接达标的成员挂入该簇，剩余成员重新选中心，禁止通过中间题传递挂靠。
- `report.build_clusters()` 新增 `representative` / `representative_index`，canonical 标题与报告样例
  统一使用该代表题；旧 `canonical_id` 粘性、topic 多数票、distinct collection witness 和人工候选状态保持。
- 增量路径原本就只与既有 `title_norm` 代表题比较，继续保留旧中心，不重排已有簇；因此增量与全量的具体
  拆分可能不同，但都满足星形不变量。人工 approved 候选仍是显式例外，只由 `--apply-candidates` 消费。
- `canonical_audit` 改判“成员是否直连代表题”；高相似题对跨簇可能是中心竞争，不再单独判 FAIL。
  同簇非代表题之间的低相似对保留计数，新增 `pairs_member_below_anchor` 与 `star_violation_samples`。

兼容与回滚：没有 schema、表结构或 CLI 参数变更；`build_clusters()` 只增字段，旧调用方可继续忽略。
代码回滚即恢复旧 DSU 口径；若生产重建后拆分不可接受，恢复重建前的 `kb.sqlite` 备份。正式应用前必须
热备份、全量重建 canonical、跑星形审计并核对簇数/variants/witness；本轮未在生产库执行重建。

回归：四题路径中尾题与代表题仅 0.579，旧实现会把四题并成一簇；新实现拆为 3+1，且所有成员直连中心。
另覆盖输入顺序、重复题、正向改写、短题实体冲突、全量/增量落库、合法星形低相似对和中心竞争审计。

# 42 · 插件方案（mianjing-kb）

> 状态：现行 · 最后更新：2026-11-22 · 适用版本：无（工具链文档）

## 一、结论

**必装 2 个，按需 4 个，其余不装。** 这个仓库已经有 72 个测试文件、双版本 CI、privacy 门禁，插件能补的只有两块：**大仓库导航**和**冷读评审**；生成能力与"从零搭流程"在这里是负资产。

配套的处理方案见 `41-Claude-Code处理方案-2026-11-22.md`；本文只管"装什么、为什么、怎么验收"。

---

## 二、选型逻辑（三条判据）

1. **能省上下文才算值**：67 个模块、单文件最大 97 KB，任何"把大文件塞进主对话"的方案都是反效果。
2. **能提供独立视角才算值**：已经有严格测试，缺的是"没参与写码的眼睛"，不是更多代码。
3. **碰生产数据的一律拒绝**：语料根、`build/` 库、LLM 费用——无人值守循环类插件直接排除。

---

## 三、必装（2 个）

### 3.1 superpowers

- **理由**：仓库里已有 `.superpowers/sdd/` 过程台账（`2026-11-21-t4-t5-t18-lowrisk`、`修复方案-2026-11-19`），说明这套 SDD 流程本来就在用；装插件是把"技能"从手工脚本升级为可复用能力。
- **在本仓库的用法**：
  - `brainstorming`：改门禁判据（`quality_rules` / `gate` / `label_quality`）前，强制先确认"判据变严会误杀哪些正常样本"。
  - `writing-plans`：一个 T 编号拆成 2–5 分钟原子任务，每任务带验证命令（fast 档）。
  - `systematic-debugging`：切题误判这类问题最忌"凭直觉改正则"，四次阶段法正合适；三次失败转架构复审的红线也需要。
  - `verification-before-completion`：防止"测试只跑了子集就宣布修好了"。
- **成本实测**：常驻 **~706 tokens**（`claude plugin details superpowers` 实测），在 2k 预算内。

### 3.2 code-review

- **理由**：仓库的评审文化很重（docs 里有 02/05/11/17/23/24/27/39 等多份评审报告），但人是瓶颈。`code-review` 用多 agent 分维度审 diff 并输出置信度，正好补"每轮小改动的日常评审"这个空档。
- **在本仓库的用法**：完成一个 T 之后、提交前跑一次；重点看它给的**置信度**——低置信度条目里往往是"看起来不对但其实有测试兜住"的误报。
- **和 `pr-review-toolkit` 的区别**：后者偏 PR 流程分维度（注释/测试/类型/质量），适合真走 PR 时再装。日常单人提交用 `code-review` 更轻。

```powershell
cd D:\Project\my\vibe-work\mianjing-kb
claude plugin install superpowers@claude-plugins-official -s project
claude plugin install code-review@claude-plugins-official -s project
```

`-s project` 让配置进 `.claude/settings.json` 随仓库走；本仓库建议坚持 project scope，避免个人全局配置影响其他项目。

## 四、按需（4 个，用完可卸）

| 插件 | 什么时候装 | 为什么不是常驻 |
|---|---|---|
| **pyright-lsp** | 要给 `chunker` / `canonical` / `db` 做类型级导航与跳转时 | 包内有 523 处返回类型注解，pyright 能干活；但项目只跑 ruff(E,F,W)，没启用类型检查，strict 模式会炸出一片，**装后先用 basic 模式** |
| **github** | 需要批量看 PR / CI 失败原因 / issue 时 | 远程是 SSH，日常 push 用不到 MCP；排查 CI 失败时价值高 |
| **session-report** | 月底复盘 token 消耗、缓存命中、子代理开销时 | 这个仓库任务颗粒小、会话多，成本容易失控，定期看一次足够 |
| **claude-md-management** | `CLAUDE.md` 写到第二版、开始漂移时 | 一次性审计工具，平时不需要 |

**context7** 归到按需里的"临时装"：查 `fastembed` / `sqlite-vec` / `pymupdf` 的版本差异时开，查完卸。这些库文档变动快，但你的用量不够常驻。

## 五、明确不装（附理由）

| 插件 / 类型 | 不装的理由 |
|---|---|
| **serena** | 已有 `docs/33` 代码地图 + pyright 可选；两套语义导航重叠，常驻成本不值 |
| **ralph-loop** | while-true 无人值守循环，对着生产语料根与 `build/` 库跑，风险不可接受 |
| **code-simplifier** | 它爱动结构；本仓库 `chunker.py` 97 KB 有大量历史兼容分支，自动"简化"等于制造回归 |
| **feature-dev** | 与 superpowers 七阶段重叠，双门禁互相打断 |
| **frontend-design / playwright** | 无前端、无页面；`kb demo` 已经覆盖端到端 |
| **各类 database 连接器** | 本地 SQLite 是生产数据，让 AI 直连查询的收益远小于误操作风险 |
| **claude-security** | 已有 `privacy_scan` 与高危工具测试；再加一层重型扫描是重复 |
| **receipts / champion-kit** | 面向团队汇报场景，个人项目用不上 |

## 六、MCP 方案

| MCP | 装否 | 说明 |
|---|---|---|
| **GitHub** | 按需 | CI 失败排查、PR 语境下读完整 diff；OAuth 接入 |
| **SQLite（只读）** | **不装** | `build/kb.sqlite` 是生产数据。要查表结构就 `kb status` 或只读脚本，不要让 AI 拿一个能写的连接 |
| 其他（filesystem / browser / 数据库云） | 不装 | 与内置能力重复或与本仓库无关 |

## 七、成本预算与校准

- 规则：常驻插件"每轮固定开销"合计 **≤ 2k tokens**（256k 上下文的 1% 内）。当前 superpowers 706 + code-review 少量 ≈ 预算内。
- 量法：`claude plugin details <name>` 看 `Always-on`；`claude plugin list` 确认 scope 与启用状态。
- 校准：装完跑一周，对比"装 code-review vs 只用自定义 code-reviewer subagent"的返工次数与耗时。若 subagent 版本已够用，就卸插件省常驻。
- 这个仓库的 token 大头不在插件，在**大文件误读**——先执行 41 号文档的 §4 读法，再考虑加插件。

## 八、安装前置：网络

本机 git 已对 `github.com` / `api.github.com` / `raw.githubusercontent.com` 配了代理（`http.https://github.com.proxy=http://127.0.0.1:7890`），插件市场的 HTTPS clone 才能通。

- 该配置依赖本机 7890 代理常驻；代理关掉后插件安装/更新会重新报 `Could not connect to github.com:443`。
- 仓库自身的远程是 SSH（`git@github.com:...`），不走这条 HTTPS 代理链路，push 不受影响。
- 临时应急（不动全局配置）：

```powershell
$env:HTTPS_PROXY='http://127.0.0.1:7890'; $env:HTTP_PROXY='http://127.0.0.1:7890'
claude plugin install <name>@claude-plugins-official -s project
```

## 九、验收清单

## 十、回滚

```powershell
claude plugin uninstall superpowers
claude plugin uninstall code-review
```

再从 `.claude/settings.json` 删掉对应 `enabledPlugins` 条目。project scope 保证回滚只影响本仓库。

## 3. 当前阈值（两套口径，**不同指标，不是重复配置**）

| 口径 | 用途 | 阈值 | 唯一来源 |
|---|---|---|---|
| 三态报告（`pass/review/fail`） | 决定哪些件进转换/抽题 | 异常字符比 ≥ **0.02** → fail；CJK 比 < **0.15** → review；可见字符数 < **100** → fail | `mianjing_kb/gate.py` 的 `TH_BAD/TH_CJK/TH_MIN`（`TH_MIN` 引 `config.TEXT_MIN_CHARS`，与 `extract.MIN_CHARS` 单源） |
| 四态台账（`gate_results`） | 记录文本质量（`pass/low_cjk/garbled/non_content`） | 乱码比 > **0.01**；有效字符比 < **0.90**；可见字符 < **800** | `mianjing_kb/kb/config.py` 的 `GATE_GARBLED_MAX / GATE_VALID_MIN / GATE_MIN_VISIBLE / GATE_CJK_MIN` |

原则：**CJK 下限单源（0.15）**；其余数值服务于不同问题（"分流" vs "台账分档"），不强行合并。
`gate --audit` 把三态报告映射进四态台账：`pass→pass`、`review→low_cjk`、`fail(乱码)→garbled`、
`fail(过短/产物缺失)→non_content`，并同步 `source_documents.gate_result`。报告侧指标先去掉空白、
Markdown 语法/代码围栏/分页标记，长度按可见字符算；`--md-dir` 仍按 `textmetrics` 四态口径。
**语义边界**：`pass` 只代表“没有可识别的非中文垃圾字符 + 长度/CJK 达标”，不等于文本可读；
ToUnicode 错映射成正常汉字的 mojibake 识别不出来，需人工抽检/二元组可信度等补充手段。
调参只改上述两处，禁止在脚本里另写一套数；聚类参数是 CLI（`report/canonical --dist/--jac`），评测基线见 `30`。

## 5. 稳定键契约（现状与目标）

| 对象 | 现用键 | 稳定性 | 结论 |
|---|---|---|---|
| `source_documents` | `doc_hash`（sha256[:16]） | 稳定 | **唯一可跨库引用的源键** |
| `questions` | `q_key = (doc_hash, q_norm_hash)` | 稳定 | **T29 已落地**；`qid` 只作行号，禁止跨库关联 |
| `label_facts` | `q_norm_hash` | 内容键；题干改一字失联 | **决策纪要 2026-11-19：主键保持 `q_norm_hash`，不迁 `q_key`**；标签是内容事实，同文本跨文档复用；变体链路仍用 `q_key`。017 加唯一索引、`normalizer_version`、`q_norm_sample`、`source/labeled_at/confidence` |
| `vec_questions` | `rowid=qid` + `q_key` metadata | 重建不漂移 | KNN 过滤用 `topic/qtype/difficulty` metadata，外部引用用 `q_key` |
| `canonical_questions` | `sha(q_norm(代表题干))` | 代表变体变则换 ID | 已知不稳定；增量吸附只增不改 |
| `question_variants` | `sha("variant:" + q_key)` | `q_key` 稳定；seq 移位不改身份 | 全量重建/增量吸附共用；增量入口先清理 q_key 已消失的旧变体 |

**label_facts 主键决策（2026-11-19）**：主键保持 `q_norm_hash`，不迁移到 `q_key`。标签描述题目内容，
不是某份文档里的单次出现；同一归一题干跨文档只标一次，`extract.store` 仍按 `q_norm_hash` 重挂。
`variant_id` / `canonical_dependents` / `merge_candidates` 继续用 `q_key`，两条链路互不冲突。
`label_overrides(q_key, ...)` 暂不建：生产 `label_facts` 目前 0 行，按主键冲突 SQL 审计为 0；若未来
同一 `q_norm_hash` 在 ≥2 个 topic 下大量出现，再建单次覆盖表，解析优先级
`label_overrides(q_key) > label_facts(q_norm_hash)`。

**T29 已实现**：`questions.q_key` 唯一索引；`(doc_hash,q_norm_hash)` 重复题在迁移/抽取时按“答案最长”保留一条
（生产 20,984 → 20,010）；`vec_questions` 增 `q_key` metadata。`refresh` 默认自动判断：
结构/题集指纹匹配则 `copy_vec`，`vec_schema_old / vec_meta_missing / vec_set_mismatch` 自动 `--reembed`；
显式 `--copy-vec` 失败即中止。`canonical --incremental` 与全量 `--jac 0.7` 同口径：
≥0.7 吸附，0.65–0.7 只登记 `merge_candidates`，<0.65 新簇；候选由
`--candidates/--approve/--reject/--apply-candidates` 人工消费。
`canonical_dependents` 承担 witness 增量；`manifest --rollback [--apply]` 按批回滚。

**归一/聚类口径（2026-11-19 v2）**：`question_freq.normalize` 先 NFKC，再映射代码符号
（`C++→cpp`、`C#→csharp`、`&&→and`、`&→bitand`、`i++→ipostinc`、`++i→preinci`），最后清洗；
CJK 保留 `\u3400-\u4dbf`、`\u4e00-\u9fff`、`\uf900-\ufaff`。`config.NORMALIZER_VERSION="nfkc-clean-v2"`。
归一升级用 `migrate_norm.py`：默认只出 old→new 快照，`--apply` 同事务更新 `questions` 与
`label_facts`，生产已 apply：2,299/20,010 条 hash 变化、0 删除；canonical 已重建。
近重复聚簇改为 2-gram 倒排 + 前缀过滤 + Jaccard 精确判定，SimHash `--dist` 不再参与判定；
question_freq CLI 的 Top 排序主键改 `n_collections`，与 `canonical.witness` 的 distinct collection 对齐。

**哈希长度口径**：`doc_hash = sha256[:16]` 只作行键/跨库引用；`source_documents.sha256` 存完整 64 位。
intake 判重命中短指纹后**再比完整 sha256**（不同则记 `hash_collision`）；`purge_origin` 删原件前
同样要求完整 sha256 相等（短指纹撞车 → 拒绝删除），不靠 16 位前缀做“内容相同”的结论。
